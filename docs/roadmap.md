## 1. ゲームの終わり方（クリア条件）

### 1件の症例の終わり
報告する → 指導役の講評 → 医師からの返信 → 1件終了。
正解を当てることがクリアではない。判断して、その結果を受け取るまでが1件。
- best … 患者が助かり、医師の信頼が上がる
- ok … 患者は問題ないが、余計な手間や遅れが出た
- poor … 患者に不利益が出るか、医師の信頼が下がる

**poorでもゲームオーバーにしない。** やり直させると正解を覚えるゲームになる。
返信を読ませ、信頼度を下げ、次に進む。失敗の記憶の方が残る。

### シフト制
1周は一晩（または一日）のシフト。出勤 → 症例が数件流れる → 退勤で集計。
```
本日の報告  6件
  適切     4件
  許容     1件
  要改善   1件
医師からの信頼度  62 → 65
```

### 信頼度と最終クリア
シフトを重ねると医師からの信頼度が上がる。
一定に達すると「今日は三嶋さん休みです」という申し送りが届き、
ナビも索引もない一晩を一人でやり切る。それが本当のクリア。
指導役が離れていく段階設計（characters.md）は、そのままシフトの積み重ねに対応する。

未決：信頼度の計算式、1シフトの症例数、信頼度が落ちたときの扱い。

## 2. 手書き症例と生成症例

| | 手書き | 生成 |
|---|---|---|
| 目的 | 新しい判断の型を教える | 覚えた型を反復する |
| 指導役の台詞 | あり（2人分） | なし |
| 閉じ方 | 講評＋医師の返信 | 医師の返信のみ |
| 出る場所 | 新人研修、上級の要所 | 上級のランダム |

**生成症例には指導役の台詞を付けない。** 付けると症例ごとに文章が要り、そこで数が止まる。

### 病態テンプレート（conditions.json）に持たせるもの
- 根っこの値の範囲（重症度で動く）
- 年齢・性別による補正
- バイタルの範囲
- 背景リスク（例：腎不全 → 高K血症のリスクあり）
- 正解の報告レベル（自動判定できないものは指定）
- 医師の返信テンプレート（best / ok / poor）

40病態 × 検体トラブル × 前回値 × バイタル で数千件に見せられる。

### 生成症例の正解判定（要言語化）
手書き症例から判定ルールを抽出してから実装する。二段の症例（症例7）は一本目の cap も
ルールの一部になる。マークと疑いが入ったぶん、
「どの項目を抜いたか」「検体側の何を疑ったか」も判定材料になる。例：
- パニック値超え＋検体トラブルなし → 緊急
- パニック値超え＋検体トラブルあり＋背景リスクなし → 再採血
- パニック値超え＋検体トラブルあり＋背景リスクあり → 付記して緊急＋再採血
- Δチェック該当＋検体正常＋バイタルが矛盾しない → 至急
- 緊急報告のマークは急ぎの1項目だけ。並べると受け手が探すことになる（症例4）

**ルールを先に書かない。** 手書きで型を出し切ってから逆算する。

## 3. 患者情報（バイタル・主訴）

結果画面の患者情報欄に出す。検査値の解釈を助ける材料であって、病名を推理させるためではない。

### 出すもの
- 依頼元（ER / 内科外来 / 病棟）
- 主訴を一行（「発熱と咳」「黒色便」）
- バイタル（脈拍・血圧、必要なら体温・SpO2）
- 既往が一行（「透析中」「慢性腎不全でフォロー中」）

### 出さないもの
身体所見、経過の詳細。検査値を見ずに答えが出せてしまう情報は入れない。

### 注意
バイタルと検査値が矛盾してはならない（高Kなのに頻脈、など）。
生成症例に移るとき、病態テンプレートにバイタルの範囲を持たせる。

## 4. 逆引き辞典（未着手）

用語辞典（`data/glossary.json`。言葉を引く・一語三行）は実装済み。ここで書くのはその先、
**所見から引く判断の辞典**。今の索引は「項目から引く」、辞典は「言葉から引く」、
逆引きは「所見から引く」。実務の思考順に合わせる。
```
Kが高いとき   … まず溶血・EDTA混入・採血手技を除外。腎機能とあわせて見る。
               ALTが動かずLD・ASTだけ上がっていれば溶血の指紋
Hbが急に下がったとき … 出血、希釈、前回値との整合、MCVで系統を見る
PLTが低いとき … EDTA凝集による偽性減少をまず疑う
```
30項目程度。根拠のある内容のみ。断定を避け「まず何を除外するか」に寄せる。
`data/reverse.json` として索引と同じ構造で持つ。

### 時間コスト（上級モードで）
- 新人モードは時間無制限なのでコストなし
- 上級では読むと時間が減る。ただし読んでいる間も装置は動き続ける
- 一度読んだ項目は次から短時間で開ける
- 「読むか読まないか」ではなく「今読むか、後で読むか」の判断にする

**時間が惜しくて読まなくなると学習が止まる。** 調べるのが常に損にならない設計にする。
内容の作成は新人モードの間からできる。時間コストは上級の実装と一緒に入れる。

### 症例7以降の候補（検査室ならではの判断。すべて手書き）
- 担当医が手術中で電話に出ない。誰に上げるか
- 前の技師が通常報告で流していたものを引き継いで気づく

- 患者名と検体情報が合わない
- 検体量が足りず、全項目は測れない。何を優先するか

### 指導役の講評の範囲（決定事項）
指導役が講評するのは、**その症例で教えたい判断に関わる分岐だけ**。
それ以外の分岐は医師の返信のみで閉じる。全分岐に台詞を書くと持たない。

## 7. 操作メカニクス（2026-09-08 追加）

操作を四段階にする。`見つける（マーク） → 疑う（タブ） → 調べる → 報告する`。
今回入れたのは「マーク」「疑う」と、別軸の「割り込み」。仕様は docs/mechanics.md。

| 段階 | 状態 |
|---|---|
| 見つける（マーク） | 実装済み。マークした行だけが報告に載る。0件でも報告できる |
| 疑う（タブ） | 実装済み。`data/suspects.json` の6つ。病名は並べない |
| 調べる | 未着手。検体目視・ID照合・塗抹・病棟へ電話。次の段階（進め方 3-b） |
| 読める画面 | 実装済み。辞典・組み立て式コメント・指さし（docs/readable.md） |
| コメント（所見一覧） | 実装済み。全症例で同じ一覧から選ぶ。判定は `when.comment` の must / any / forbid（docs/comment-list.md） |
| 報告する | 実装済み（通常／至急／緊急） |
| 割り込み | 実装済み（症例3→4）。上級でランダム化（進め方 8） |
| 差し戻し | 実装済み（症例7）。`then` / `cap` / `followup`。ランダム化はしない |

### 次にやること（「調べる」を入れるとき）
- 行動そのものに結果を返す（検体を見たら溶血の見え方が分かる、など）
- 上級では行動に時間コストを載せる。新人モードでは無料のまま
- 判定に `actions` を足す。marks / suspects と同じく、書かなければ不問にする
