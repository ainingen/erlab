# ERLAB 操作メカニクスの追加（2026-09-08）

## 背景

現状の操作は「読んで、三つのボタンから一つ押す」だけ。判断が頭の中で完結し、画面に残らない。
プレイヤーが**何を見つけたか**が評価されないため、面白さが出ない。

そこで操作を四段階にする。

```
見つける（マーク） → 疑う（タブ） → 調べる（行動） → 報告する
```

今回はこのうち「マーク」「疑う」と、別軸の「割り込み」を実装する。「調べる」は後回し。

---

## 1. マーキング

### 操作
- 結果テーブルの行をタップ／クリックすると反転（マーク状態）
- 再度タップで解除
- マークした行だけが報告に載る（報告ダイアログにマーク済み項目が並ぶ）
- マーク0件でも報告はできる（＝「異常なし」の報告）

### 表示
- マーク行は背景を反転（暗い地に明るい文字）。色ルールの例外として、これは値の重さではなく「選択状態」の表示
- 報告ダイアログの上部に「報告対象：K, Cre」のように列挙

### 評価への組み込み
`choices.when` に `marks` を追加できるようにする。
```json
"when": { "report": "emergency", "marks": { "must": ["K"], "max": 1 } }
```
- `must` … 含まれていなければ不一致
- `max` … マーク数の上限（超えたら不一致）
- `forbid` … 含まれていたら不一致
- 書かなければ不問（既存の枝はそのまま動く）

---

## 2. 疑いタブ

### 操作
マークした行に対して、疑いを1つ以上付ける。病名ではなく**検体・検査室側の疑い**のみ。
```
[採血に問題なし（値は患者由来）] [溶血] [凝集] [希釈・点滴側] [取り違え] [前回値との乖離]
```
- マーク行をタップすると、行の下にタブが展開
- 複数選択可（5-bは「採血に問題なし」＋「溶血」）
- 何も選ばなくても報告できる（新人向け。ただし評価で差が出る）

### 評価への組み込み
`choices.when` に `suspects` を追加。
```json
"when": { "report": "recheck", "marks": { "must": ["K"] }, "suspects": { "K": ["hemolysis"] } }
```
- 指定した項目に、指定した疑いがすべて付いていれば一致
- 指定外の疑いが付いていても不問（`exact: true` で厳密一致にできる）

### 疑いのID
```
real        採血に問題なし（値は患者由来）
hemolysis   溶血
clot        凝集
dilution    希釈・点滴側
mismatch    取り違え
delta       前回値との乖離
```

## 3. 既存症例の評価の書き換え

マークと疑いが入るので、症例1〜6の choices を以下の方針で更新する。
講評の台詞は変えない（マーク条件を足すだけ）。

| 症例 | best の条件 | 補足 |
|---|---|---|
| 1 | 通常、マーク0 | 何かマークして通常 → ok（「それ、異常じゃないよ」の講評は不要。医師返信のみ） |
| 2 | 通常、マーク0 または CRPのみ | CRPに `real` が付いていれば良い。付けなくてもbest |
| 3 | 通常＋コメント、Hbをマーク、`real` | MCV/MCHも一緒にマークしてよい（max 3） |
| 4 | 緊急、Kのみマーク、`real` | K以外を一緒にマーク → ok「何が緊急か伝わりにくい」（新しい短い講評1本×2人。下記） |
| 5 | 再採血、Kをマーク、`hemolysis` | `real` だけ付けて緊急 → poor（既存の「検体状態、見た？」） |
| 5-b | 緊急＋再採血、Kをマーク、`real`＋`hemolysis` | `hemolysis` のみで再採血 → poor（既存の「採り直しただけ？」） |
| 6 | 至急＋コメント、Hbをマーク、`delta`（`real` も可） | `mismatch` を選んで再採血 → ok（既存の「取り違えを疑ったのね」） |

### 症例4に足す講評（K以外も一緒にマークして緊急）

**かなえ / normal**
> 電話したのは合ってる。
> でも報告に9個並べたら、向こうは「どれが急ぎ?」ってなる。
> 緊急のときは、急ぎの一つだけ。他は後で通常で送ればいい。

**悠介 / normal**
> 緊急報告の判断は正しいです。
> ただし報告に多数の項目が並ぶと、受け手は緊急性のある項目を探すことになります。
> 緊急報告には緊急の項目だけを載せ、他は通常報告で補ってください。

## 4. 割り込み（症例4）

### 挙動
症例3を開いている途中（結果表示から一定時間後、または症例3の報告直前）に、症例4がERから割り込む。

1. ヘッダーバーが赤に変わる（`state: interrupt`）
2. 受付一覧の先頭に症例4が「至急」で割り込み、数秒点滅
3. 院内メッセージに ER からの依頼が届く
4. 指導役の一言（下記）
5. 症例4を開くとヘッダーに「至急対応中」。症例4の報告完了で白に戻る

### 症例3を放置した場合
症例4を報告した後、症例3が未報告なら申し送りで軽く指摘（poor扱いにはしない）。

**かなえ / normal**
> ……で、さっきの貧血の人。まだ送ってないよね。急がないけど、忘れない。

**悠介 / normal**
> 先ほどのHb低値の検体が未報告です。緊急性はありませんが、忘れずに送ってください。

### ER からのメッセージ
> [ER 当直医]
> 至急でお願いします。慢性腎不全の67歳男性、倦怠感と脱力で搬送。
> 血算・生化学、急ぎで。

### 割り込み時の指導役の一言

**かなえ / alert**
> ……来た。手、止めて。
> 今の貧血、急がないでしょ。先に至急。

**悠介 / alert**
> ERからの至急です。
> 現在の検体は緊急性がありません。至急を先に処理してください。

### 頻度
新人研修では症例4の1回のみ。上級モードでランダム化する（roadmap 8 に含める）。

### 色ルールとの関係
結果テーブル内の色ルール（値の重さを色で示さない）はそのまま。
ヘッダーの赤は「画面の状態」の合図であり、値の判定ではない。CLAUDE.md にこの区別を追記。

## 5. 実装順

1. マーキング（表示＋ `marks` 評価）
2. 疑いタブ（表示＋ `suspects` 評価）
3. 既存症例の choices 更新＋症例4の追加講評
4. 割り込み（症例3→4）
5. 症例0のチュートリアルに、マークとタブの説明を1ステップ追加（下記）
6. テスト、characters.md / roadmap.md 更新

### 症例0に足すステップ（0-6の後、0-7の前）

**かなえ / normal**
> それと、おかしいと思った行はタップして。反転する。
> 反転させた行だけが報告に載る。全部載せたら、向こうは何を見ればいいか分からない。
> 反転した行にはタブが出る。「溶血のせいか」「採血に問題ないか」。そこも選べる。……最初は選ばなくていい。

**悠介 / normal**
> 異常と判断した行はタップしてマークしてください。マークした行だけが報告に載ります。
> マークした行には、疑いを選ぶタブが出ます。「採血に問題なし」か「溶血」か、といった検体側の見立てです。
> 最初のうちは空欄でも構いません。慣れてきたら選んでください。

## 6. やらないこと

- 病名をタブに並べない（医師ゲームに戻る）
- 自由記述の入力欄は作らない（評価できない、スマホでつらい）
- 時間制限はまだ入れない（roadmap どおり上級で）
- 「調べる」行動（検体目視・ID照合・塗抹・病棟へ電話）は次の段階
