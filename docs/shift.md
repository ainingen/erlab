# ERLAB シフト制と信頼度（2026-09-09）

roadmap 1章・進め方 5。未決だった三つ——**計算式・1シフトの症例数・信頼度が落ちたときの扱い**——を決める。
生成症例の供給（進め方 6）は含めない。ここで決めるのは**枠**。症例の中身は今ある手書き9本と g01 で回す。

---

## 0. 結論

- 1周＝一晩。**5件**流れて退勤、集計
- 信頼度は累積ではなく **直近10件の窓**。best +2／ok +1／poor −3。窓の合計（0〜20）を5倍して 0〜100 で見せる
- **80 以上**で翌晩が「三嶋さん休み」の晩。その晩を **poor ゼロ**で終えたら本当のクリア
- 落ちても罰は無い。指導役の晩が続くだけ。ゲームオーバーも無い
- 新人研修（症例0〜7）は最初の一晩として扱う。研修中も窓は数えるが、表示は初めての退勤から

---

## 1. 一晩の流れ

```
出勤（申し送り） → 症例が5件、受付一覧に並ぶ → 5件とも閉じたら退勤 → 集計画面 → 次の晩
```

- 受付一覧には**最初から5件並べる**（研修と同じ見せ方。順に開く必要はない）
- 5件とも報告し終えるまで退勤できない。割り込み・差し戻しがあっても件数は変えない（割り込みは既存の症例側設定）
- 集計画面は roadmap 1章の形そのまま：

```
本日の報告  5件
  適切     3件
  許容     1件
  要改善   1件
医師からの信頼度  60 → 65
```

- 集計の下に「次の晩へ」。押すと次の申し送りが届く
- **研修（症例0〜7）は「一晩目」**。件数は5件ではなく既存の全部。退勤の集計はこの晩から出す

### 申し送りの文面

`data/messages/common.json` に足す（`kind: handover`、`from_mentor` は状況で変える）。

| ID | いつ | body |
|---|---|---|
| `msg_shift_night_start` | 通常の晩の出勤 | 「今晩は5件の予定です。順番はどれからでも。全部閉じたら退勤してください。」（`from_mentor: true`, normal） |
| `msg_shift_night_end` | 退勤時（集計の上に一行） | 「お疲れさまでした。集計を出します。」（`from_mentor: true`） |
| `msg_shift_absent_start` | 指導役不在の晩の出勤 | 「今日は{mentor}さん休みです。ナビはありません。索引の言葉と見る順番は使えます。5件、一人でお願いします。」（`from: 中央検査部`、`speaker` なし） |
| `msg_shift_absent_clear` | 不在の晩を poor ゼロで終えた | 「今晩、指導役なしで5件通しました。要改善はありません。明日から、あなたの席は隣ではなく向かいです。」（`from: 中央検査部`） |
| `msg_shift_absent_fail` | 不在の晩に poor が出た | 「今晩の分、{mentor}さんが明日読みます。明日は隣に戻ります。」（`from: 中央検査部`） |

`{mentor}` は選択中の指導役の姓（三嶋／羽鳥）。指導役が2人いるので「三嶋さん休み」を固定文にしない。

## 2. 信頼度

### 2-1. 計算

- **直近10件の窓**。症例を1件閉じるごとに最終評価を窓の末尾に入れ、11件目で先頭を落とす
- 点：best **+2**／ok **+1**／poor **−3**
- 窓の合計を 0 未満は 0、20 超は 20 に切る。表示は **×5（0〜100）**
- 「聞いた症例は best にならない」（cap ok）は既存のまま。窓は最終評価を見るので、聞いた症例は自動で +1 止まりになる。別の減点は足さない
- 差し戻し（`then`）は**二本で1件**。最終評価（min）を1回だけ入れる
- 割り込みで放置した症例は評価を下げない（既存）。窓にも普通に入る

数字は全部 `data/shift.json`。コードに埋めない：

```json
{
  "cases_per_night": 5,
  "window": 10,
  "points": { "best": 2, "ok": 1, "poor": -3 },
  "display_scale": 5,
  "absent_threshold": 80,
  "_note": "..."
}
```

### 2-2. なぜ窓か

累積だと序盤の poor が一生残るか、逆に稼ぎ切ったあと何をしても安全になる。
窓なら「最近どうか」だけを見る。落ちても戻せる。緩んだら落ちる。

### 2-3. 表示

- 集計画面だけ。**症例の途中では出さない**（数字を追いかけるゲームにしない）
- 「60 → 65」の形。最初の晩は「— → 45」

## 3. 指導役不在の晩

### 3-1. 来る条件

退勤の集計で信頼度が **80 以上**なら、次の晩は不在の晩。申し送りは `msg_shift_absent_start`。

### 3-2. その晩の画面

| | 通常の晩 | 不在の晩 |
|---|---|---|
| ナビ（見どころ） | 手書きは台詞、生成は無し | **出さない** |
| 聞く | 押せる。許容どまり | 既存の `msg_ask_no_mentor`。上限は落とさない（既存） |
| 索引の「項目」 | 開く | **開かない**（タブを外す） |
| 索引の「言葉」・「見る順番」 | 開く | 開く（調べるのが常に損にならない線） |
| 講評 | 出る | **出ない**。医師の返事だけ |
| 申し送り | 指導役の名義 | 中央検査部の名義 |

これは既存の `mentor: false` の日の扱い（investigate.md §8、characters.md「上級」）と同じ。**晩に `mentor: false` を持たせる**だけで症例側は触らない。

### 3-3. 終わり方

- **poor ゼロで退勤 → クリア。** `msg_shift_absent_clear` を集計の上に出す。以後は同じ枠で続く（エンドレス）。クリア済みの印は保存する
- **poor が1件でも → `msg_shift_absent_fail`。** 翌晩は指導役が戻る。**窓は動かさない**（poor の −3 はもう入っている。二重に下げない）。
  ただし戻った晩は、信頼度が80以上でも不在にしない（**最低1晩は指導役の晩**）。その次の退勤で改めて 3-1 を見る
- クリア後も 3-1 は生きる。80以上なら不在の晩、80を切れば指導役が戻る

### 3-4. なぜ罰を作らないか

poor は医師の返事で受け取るもの（roadmap 1章）。窓の −3 と、指導役が戻ることで足りる。
不在の晩を「失敗したら振り出し」にすると、不在の晩だけ慎重になる遊び方を教えてしまう。

## 4. 症例の供給（今の材料で回す）

生成の本体は進め方 6。ここでは**枠に5件を入れる関数**だけ置く。

- `pickNightCases(night, pool, rng)`：晩ごとに5件を選んで返す
- いまの `pool`：**g01** と手書き **n01〜n07b**（n07 は差し戻しつきのまま入れてよい。n03 の割り込み設定はそのまま動く）
- 選び方（暫定）：g01 を必ず1件、残り4件は手書きから重複なしで。同じ晩に同じ症例を二度出さない
- 症例の順番は受付時刻順に見せる。`received_at` は晩ごとに引き直す（出勤 20:00 から 30分刻み。既存の `received_at` は研修専用の値なので、シフトでは上書きして見せる。データは変えない）
- 手書き症例は `choices` のまま判定し、講評もそのまま出る（不在の晩は出さない）。生成は規則
- 乱数の種は晩の番号。**同じ晩は同じ5件**（再現できるように）

進め方 6 でプールが厚くなったら、この関数の中身だけ替える。

## 5. 保存

- `localStorage` の `erlab.save` に一つの JSON：`{ night, window: [...], cleared, mentor }`
- 症例を閉じるたびに書く。読めなければ（PLiCy の iframe で塞がれていたら）**メモリだけで動く**。保存できない旨は出勤の申し送りの末尾に一行足す（「※この環境では進行が保存されません」）
- 「最初から」ボタンを指導役選択画面に置く。押したら確認を一度だけ取って消す
- 研修中（一晩目）も保存する。途中で閉じても、次は研修の続きから

---

## 6. 変えないこと

- poor でゲームオーバーにしない（roadmap 8章）
- 症例側のデータ（`data/cases/*.json`）は触らない。晩の状態は `mentor` フラグと `received_at` の上書きだけで作る
- 「聞く」「調べる」「辞典」「見る順番」の扱いは既存のまま。不在の晩で消すのは索引の「項目」タブとナビと講評だけ
- 信頼度を症例の途中で見せない
- 医師の返事は信頼度で変えない（医師は悪者にしない）

## 7. 実装の形（Code へ）

- `src/shift.js`：純関数で `pushScore(window, score, cfg)`、`trust(window, cfg)`（0〜100）、`isAbsentNight(state, cfg)`、`pickNightCases(night, pool, rng)`、`summarize(scores)`（集計）
- `data/shift.json`：§2-1 の数字
- `src/app.js`：出勤 → 5件 → 退勤 → 集計 → 次の晩、の状態遷移。研修（症例0〜7）を一晩目として同じ遷移に載せる
- 集計画面は既存の院内メッセージの枡で出す（別UIを作らない。design.md の方針）。表の部分は `body` の等幅3行で足りる
- 保存は §5。読み書きは一か所
- テスト：
  1. 窓：11件入れると先頭が落ちる。best/ok/poor の点が `shift.json` どおり
  2. 切り詰め：合計が 0 未満・20 超にならない。表示は ×5
  3. 不在の判定：80 以上で翌晩不在。不在の晩で poor が出たら翌晩は指導役、その次は 3-1 で見直す
  4. クリア：不在の晩で poor ゼロなら `cleared` が立ち、`msg_shift_absent_clear` が出る
  5. 供給：同じ晩の番号で同じ5件。g01 が必ず入る。重複なし
  6. 差し戻しつき症例は二本で窓に1回だけ入る
  7. 不在の晩でナビ・講評・索引の「項目」が出ず、辞典・見る順番・聞く（不在の文）は出る
  8. 保存が読めない環境でも出勤まで進む（`localStorage` を投げるモックで）
  9. 手書き9本と g01 の既存テスト（249件）はそのまま通る
