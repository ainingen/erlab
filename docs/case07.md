# ERLAB 症例7「緊急の差し戻し」（2026-09-08）

## ねらい

**医師に否定されても、値が残れば同じ強さでもう一度報告する。**

これまでの症例は「報告する → 講評 → 医師の返信」で閉じていた。症例7は、医師の返信が
**差し戻し**として返ってくる。再採血で同じ値が出たとき、プレイヤーがもう一度緊急報告できるかを見る。

検査室が持っているのは値であって、医師の見立てではない。医師が「違う」と言ったのは一本目の
話で、二本目の値はまだ誰にも伝わっていない。**電話が嫌で報告レベルを下げる**のが、この症例で
潰したい失敗。

症例7以降はナビが一行になる段階（characters.md「ナビの段階設計」）。この症例が最初の一行ナビ。

## 2. 流れ

```
一本目を読む → 報告（緊急）→ 医師「採り直して」（差し戻し）
    → 指導役の一言 → 二本目が届く → もう一度報告 → 講評 → 医師の返信 → 終了
```

1. 一本目。K 6.4 HH、溶血なし、Δあり。ナビは一行だけ
2. 緊急報告（または至急報告）すると、医師の返信が**差し戻し**で返る。症例はまだ閉じない
3. 指導役が一言（normal）。答えは言わない
4. 再採血検体が届く。受付一覧の同じ行に「再採血」の札、結果画面の下に二本目の表
5. 報告ボタンがもう一度使える。**ここが本番の判定**
6. 二本目を報告すると、いままでどおり「（あれば）講評 → 医師の返信」で閉じる

一本目で報告せずに閉じた枝（通常報告・再採血のみ）は、差し戻しに届かない。
**医師が差し戻せるのは、報告されたものだけ**。これはそのまま実装の条件でもある。

## 3. 新しい仕組み：`then` と `followup`

症例 JSON に足すのは三つ。**どれも書かなければいまの症例はそのまま動く。**

```json
"choices": [
  { "when": { "report": "emergency", "marks": { "must": ["K"], "max": 1 }, "suspects": { "K": ["real"] } },
    "then": "followup", "cap": "best",
    "headline": "緊急報告は適切。医師から差し戻しが返ります",
    "reply": null, "doctor": "msg_n07_doctor_pushback" },
  ...
],
"followup": {
  "handover": ["msg_n07_return_kanae", "msg_n07_return_yusuke"],
  "recollect": { "K": 6.2, "Cre": 1.7, "BUN": 31, "LD": 192, "AST": 25 },
  "choices": [ ... 二本目の判定 ... ]
}
```

- **`then: "followup"`** … この枝に当たったら症例を閉じず、`doctor` を届けたあと `followup` に進む。
  `reply` は `null`（講評は最後に一度だけ）
- **`cap`** … 最終評価の上限。`best` / `ok` / `poor`。書かなければ `best`。
  一本目の判断が甘かった（至急に落とした、K以外も並べた）ぶんを、二本目で挽回しきれないようにする
- **`followup.handover`** … 差し戻しのあと、二本目が届く前に出す指導役の一言。形は `nav` と同じ（配列、speaker つき）
- **`followup.recollect`** … 二本目の上書き値。書かなかった項目は一本目と同じ根っこの値から `derive.js` が作り直す。
  形は n05 の `recollect` に合わせる
- **`followup.choices`** … 二本目の判定。形は `choices` と同じ。`when` は二本目の操作だけを見る

**最終評価 ＝ min（`followup.choices` で当たった枝の `score`、一本目の `cap`）。**
順序は best > ok > poor。`followup` に入ったあとの枝に `then` は書けない（入れ子にしない）。

`recheck` の扱い：一本目で `recheck: true` を選んだ枝は**症例を閉じる**（`then` を持たない）。
二本目が「差し戻しの結果として届く」のと、「自分で採り直した」のを混ぜないため。

## 9. やらないこと

- 医師の差し戻しをランダムにしない。この症例だけ、手書きで一回
- 「医師に反論する」入力欄を作らない。返すのは報告レベルであって言葉ではない（mechanics.md 6 の自由記述の禁止と同じ）
- 一本目の正しい緊急報告を減点しない。差し戻されるのはプレイヤーの失敗ではない
- 三本目の採血は許さない（poor）。二本同じなら検体の話ではない
- 時間制限は入れない。差し戻しから二本目までの待ちは演出だけ（数秒）
- 一本目と二本目で値を大きく変えない（6.4 → 6.2）。「再採血で戻った」と読める幅にしない。
  Δ幅 1.0 の半分も動かさない

## 10. 実装との差（2026-09-08 実装時に決めたこと）

- `followup.recollect` は上書き値を `overrides` の下に置き、`accession` / `received_at` /
  `artifact` / `reply` は n05 の `recollect` と同じ位置に並べた（`buildRecollect` を共用するため）
- 4-1 の「`recheck: true` を選んだ枝は閉じる」は、表の4行目（報告なしの再採血）を指すものとして
  実装した。緊急報告に再採血を添えた操作まで poor にすると、9章「一本目の正しい緊急報告を
  減点しない」に反するため、そちらは差し戻しに入る
- 4-1 の2行目（緊急・マークと疑いは不問）は、見出しが操作と食い違うので3枝に割った。
  「K だけマークして疑いを選んでいない」「K 以外も並べた」「K をマークしていない」。
  cap はどれも `ok`、講評なし、医師は pushback で、評価は表のままにしてある
- 4-2 の「至急 または 通常」と「`{}`」は同じ評価・同じ文面なので、受け皿の1枝にまとめた
- 症例7の申し送り（`msg_n07_intro`）は仕様に無いが、症例1〜6と同じく1本置いた。
  患者の背景と「ここからナビは一行になる」ことだけを伝え、判断には触れない
