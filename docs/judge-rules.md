# ERLAB 判定ルール（2026-09-09）

roadmap §6-4。手書き症例9本（n01〜n07b）の `choices` 70枝から共通の型を取り出し、
**症例の事実から「正解の操作」を導き、操作のずれ方で評価と講評を決める**規則にした。
材料は docs/choices-table.md。生成症例（§6-5）はこの規則で判定する。手書き症例は今までどおり `choices` で判定し、規則はそれを再現できることをテストで示す。

## 0. 結論

- choices-table.md §c の「同じ形の when で score が割れている」6グループは、**全部が正当な差**。分かれる理由は下の四つの事実。揺れは無い
- 手書き9本の枝は、**7つの事実 → 8つの正解型 → 16種のずれ** に還元できる
- ずれの評価は「患者に害が及ぶ向きか」で poor と ok が分かれる。ok の中の順位は「何が欠けたか」で決まる

## 1. 症例の事実（エンジンが自動で導く）

| 記号 | 事実 | 導き方 |
|---|---|---|
| **P** | パニック値がある（HH / LL） | フラグ |
| **A** | 検体トラブル | `artifact`。二段に分ける：**A₁**＝値はまだ使える（溶血1+・2+）／**A₂**＝値が使えない（溶血3+、凝集・フィブリン（PLT）、希釈、量不足） |
| **D** | 前回値との乖離（Δ） | 前回値との差が Δ しきい値を超える項目がある |
| **M** | 別人の疑い | 前回値との差が「変わらないはずの項目」で出ている：MCV の差が **6 fL 以上**、または Cre が性別・前回から説明できない向きに **半分以下／2倍以上**、または Δ のある項目の向きがそろっていない |
| **X** | 検体トラブルがあっても値は患者由来 | P があり、前回値が同じ向きにすでに異常（例：K 5.8 → 6.0 に溶血2+） |
| **R** | 差し戻し後の二本目 | `followup` 段。二本目が一本目と同じ向き |
| **N** | 異常なし、または軽度の H/L のみ | P も D も M も無く、A も無い |

優先：**M > A₂ > P > D > A₁ > N**。M があれば A や P は別人の値なので判断に使わない。

**鍵の項目（key）**：判断を決めている項目。P があればパニックの項目、M なら指紋の項目（MCV）、D なら Δ の項目、A₂ なら壊れた項目（溶血なら K、凝集なら PLT）、それ以外なら最も強いフラグの項目。マークと疑いはこの項目に付ける。

## 2. 正解の型（事実 → 正解の操作）

正解は六つ組：**報告レベル／再採血／コメント／マーク／疑い／行動**。

| 型 | 事実 | 報告 | 再採血 | コメント | マーク・疑い | 行動 | 手書きの例 |
|---|---|---|---|---|---|---|---|
| T1 正常 | N | routine | なし | なし | なし（フラグのある項目だけなら可） | — | n01・n02 |
| T2 中等度 | H/L のみ、A なし、D なし | routine | なし | **あり**（real） | key に real | — | n03 |
| T3 パニック | P、A なし | **emergency** | なし | なし | key に real、**マークは key だけ** | — | n04・n07一本目 |
| T4 壊れた検体 | A₂（X なし） | 報告しない（routine のまま値を出さない） | **あり** | なし | key に A の疑い | — | n05 |
| T5 壊れていても患者由来 | P と A₁（または A₂）と X | emergency | あり | あり | key に real＋A | **call** | n05b |
| T6 変化 | D、A なし、M なし | **urgent** | なし | あり | key に delta | **idcheck** | n06 |
| T7 別人 | M | urgent（病棟に伝える。値は保留） | あり | あり（mismatch） | key に mismatch | **idcheck＋call** | n07b |
| T8 差し戻し後 | R | 一本目と同じレベル | なし | あり（recollect_same） | key に real | — | n07二本目 |

手書きに無い組み合わせ（生成症例で出うる）は次のとおり埋める：

| 事実 | 型 |
|---|---|
| A₁ と H/L（P なし） | T2 に「コメント＝A、疑い＝A」を足す。再採血なし |
| A₂ と P（X なし） | T4（値は出さない。緊急にかけない） |
| A₂ と D | T4。Δ は壊れた検体では判断しない |
| D と A₁ | T6 に call を足す（希釈を消す） |
| D かつ P（A なし） | T3（緊急が上位。コメントに delta を添えれば best） |
| P が二項目以上 | T3。マークは全部のパニック項目まで可 |

## 3. ずれの種類と評価

操作を正解と比べ、**上から順に最初に当たったずれ**で評価する。poor が先、ok が後。ずれが無ければ best。

### poor（患者に害が及ぶ向き）

| # | ずれ | 見出し（テンプレ） | 手書きの例 |
|---|---|---|---|
| P1 | P があるのに **routine**（再採血だけを含む） | パニック値を通常報告にしています | n04#8・n05b#6/#9・n07#6/#7 |
| P2 | A₂ なのに **emergency**（値を信じて電話） | 壊れた検体の値で電話をかけています | n05#5 |
| P3 | A₂ に触れずに報告（コメント無し・再採血無し） | 検体状態に触れないまま報告しています | n05#6 |
| P4 | M なのに値を患者のものとして報告（urgent/emergency、または疑い delta） | 別人の値を、患者の変化として報告しています | n07b#6/#7/#9 |
| P5 | 手がかり（A・D・M）が無いのに再採血 | 再検の理由がありません | n01〜03#1・n07二本目#3 |
| P6 | 異常が無い（N）のに routine より上 | 過剰報告です | n01〜03受け皿 |
| P7 | D があるのに routine で流した（コメントも無し） | Δを見落としています | n06#10 |
| P8 | R で一本目よりレベルを下げた | 否定されて報告レベルを下げています | n07二本目#4 |

### ok（向きは合っている。何かが欠けた）

| # | ずれ | 見出し（テンプレ） | 手書きの例 |
|---|---|---|---|
| O1 | コメントの種類が事実と合わない（A 無しに溶血、D 無しに delta、D に continued） | そのコメントは事実に合いません | n03#2・n04#2・n06#1・n05b#1 |
| O2 | P に urgent（一段下） | 届いてはいます。ただしパニック値は電話で読み返しまで取ります | n04#7・n05b#5・n07#5 |
| O3 | 一段上（D に emergency、T7 に emergency） | 向きは正しい。ただしHHでない値に緊急回線を使っています | n06#5/#9・n07b#3 |
| O4 | 必要な行動が欠けた（call / idcheck） | 判断は適切。ただし{行動名}で裏を取っていません | n05b#3・n06#3・n07b#2 |
| O5 | 必要なコメントが無い | 報告は適切。ただし理由がコメントに残っていません | n03#6・n05b#7・n06#8・n07b#5・n07二本目#2 |
| O6 | key にマークが無い／疑いが無い／疑いが違う | {key}に疑いが付いていません | n03#4/#5・n04#4・n05#3・n05b#4・n06#4・n07b#8 |
| O7 | フラグも Δ も無い項目にマーク／緊急でマークが key 以外にもある | 異常のない項目をマークしています／緊急報告に項目を並べすぎです | n01#3・n02#4・n04#5 |
| O8 | 報告が要る場面で再採血だけ（手がかりはある） | 再採血の判断は分かります。ただし報告が先です | n06#6/#7 |
| O9 | 信用できる検体に再採血を足した（報告は正しい） | 報告は正しい。ただしこの検体に再検の理由はありません | n04#1・n05#1 |
| O10 | A₁ の場面で再採血が欠けた（T5） | あと一歩、再採血まで出しておきたい場面です | n05b#8 |

### 評価の上限（cap）
- 「聞く」を使った症例は best にならない（investigate.md §8）
- 差し戻し（`then`）の cap は一本目のずれで決まる：一本目にずれ無し → best まで、ずれあり → ok まで（n07一本目#1〜#5 の cap と一致）

## 4. 講評の付け方

- 見出しは §3 のテンプレ。`{key}` `{行動名}` を埋める
- 指導役の講評は**ずれの種類ごとに2人分**（poor 8＋ok 10＝18種×2＝36本）。生成症例では症例ごとに台詞を書かない（design.md の方針）。手書き症例は今までどおり症例固有の講評
- 医師の返事はずれの種類ではなく**報告レベル×正解レベルの組**で選ぶ（既存の `doctor` メッセージを共通化。§6-5 で整理）

## 5. 手書き9本との突き合わせ

規則が手書きを再現するか、機械で確かめる。

- choices-table.md §a の「落ちる操作の例」65操作（`then` の5枝は cap で比較）を規則に通し、**手書きの score と一致するか**を見る
- 一致しない枝は「規則が間違い」か「手書きが例外」かを私が判断する。**規則を手書きに合わせて曲げるのは、その枝が型として正しいときだけ**
- 見出しの文言は一致を求めない（手書きは症例固有の文でよい）

予想される不一致（先に書いておく）：
- n05b#1（溶血だけ・real 無し → ok）：規則では O6（疑いが違う）で ok。一致
- n07一本目#8 受け皿：総当たりで届かないので比較対象外。**枝は消さない**（受け皿のテストがある。到達不能でも害はない）
- n02#3（CRP をマークして best）：規則の T1「フラグのある項目だけなら可」で best。一致

## 6. 実装の形（Code へ）

- `src/judge.js` に純関数 `deriveFacts(case, results, previous)` と `judge(facts, operation) → {score, deviation, headline, key}` を置く。UI から切り離してテストできる形
- `choices` を持つ症例は今までどおり `choices` で判定。**`choices` が無い症例だけ `judge` を使う**（手書きの挙動は変えない）
- しきい値（Δ、MCV 6 fL、Cre 比）は `data/judge.json` に出す。コードに埋めない
- テスト：
  1. 事実の導出：手書き9本それぞれの事実（P/A/D/M/X/R/N と key）が §1・§2 の表どおりになる
  2. 突き合わせ：choices-table.md §a の65操作を `judge` に通し、手書きの score と一致する。不一致は落とさず**表にして報告**（どの症例のどの枝が、規則では何になったか）
  3. ずれの優先順：同じ操作に poor と ok が両方当たるとき poor が先
  4. 生成症例の代表10通り（§2 の表の各行と、手書きに無い組み合わせ6行）で best の操作が一意に決まる
- 講評36本と医師返事の共通化は**この仕様に含めない**（§6-5 で）。今回は見出しのテンプレまで
