# ERLAB 新人が読める画面（2026-09-08）

## 背景

通しで遊んで分かったこと。**ゲームが検査室の言葉を知っている前提で組まれていて、
新人向けなのは指導役の口調だけ。**

- 「溶血」が何かを引ける場所がない。索引は項目（WBC・K…）からしか引けず、
  検体状態欄・疑いタブ・フラグ記号の言葉はタップしても何も開かない
- ナビが「検体状態と前回値を見て」と言っても、**画面のどこがそれか**が分からない
- 報告のコメント欄が自由記述で、**何を書けばいいか分からず、書けない**。
  mechanics.md 6 で「自由記述は作らない」と決めたのに、ここだけ残っていた

三つを一本で入れる。順番は **辞典 → コメント → 指さし**。
コメントは辞典の言葉で組むので辞典が先。指さしは `nav` に一語足すだけなので最後。

新しい画面は作らない。索引パネル・報告ダイアログ・ナビの三つに足すだけ。

## 1. 用語辞典

### 置き場所
`data/glossary.json`。索引（`tests.json`）とは別のファイル。項目ではなく**言葉**の辞典。
roadmap 4章の逆引き辞典（「Kが高いとき」から引く判断の辞典）とも別。あれは重くて後ろ、
こちらは軽くて最初から要る。

### 形
```json
{
  "hemolysis": {
    "term": "溶血",
    "aliases": ["溶血（1+）", "溶血（2+）", "溶血（3+）"],
    "lines": [
      "赤血球が壊れて、中身が血清に出た状態。血清が赤く見える。",
      "K・LD・AST が見かけ上高くなる。本物の異常と区別がつかない。",
      "検体状態欄に段階（1+〜3+）で出る。まずここを見る。"
    ]
  }
}
```
- **三行以内。**「何か／なぜ値がずれるか／何を見れば分かるか」の順
- 病名を書かない。検体と検査室の話だけ
- `aliases` は画面上の表記のゆれ（「溶血（2+）」のようにタップされる文字列）

### 語（16。増やすときは三行の型を守る）

| id | 語 | 三行 |
|---|---|---|
| hemolysis | 溶血 | 赤血球が壊れて中身が血清に出た状態。血清が赤く見える ／ K・LD・AST が見かけ上高くなる ／ 検体状態欄に段階（1+〜3+）で出る。まずここを見る |
| clot | 凝集（EDTA凝集） | 採血管の抗凝固剤 EDTA で血小板が固まり、装置が数えられない ／ PLT だけが見かけ上低くなる。他は正常のまま ／ 別の抗凝固剤の管で採り直すと戻る |
| dilution | 希釈（点滴側採血） | 点滴のルートの近くで採ると、点滴液が混ざる ／ 全体が薄まり、点滴の中身（Na や Glu）だけ高く見える ／ 反対の腕で採り直す |
| mismatch | 取り違え | 別の患者の検体が、この患者の名前で来ている ／ 前回値と全項目が合わない。性別と合わない値（Hb など）が手がかり ／ ID を照合し、再採血 |
| previous | 前回値 | 同じ患者の前回の結果。結果画面の右の列 ／ 「基準範囲の中か」ではなく「この人にとって変か」を見るためのもの ／ 前回がなければ空欄。あれば必ず見る |
| delta | Δ（デルタチェック） | 前回値からの動きが決めた幅を超えたときの印 ／ 検体の間違いか、患者の変化か、どちらかが起きている ／ 検体状態が正常なら、患者が変わっている |
| panic | パニック値 | 放置すると命に関わる値。項目ごとに決まっている ／ 原則、電話で緊急報告 ／ ただし検体不良が否定できるときだけ。溶血の K はそのまま電話しない |
| flags | フラグ（H / L / HH / LL） | 基準範囲の外が H・L、パニック値が HH・LL ／ 色は補助。記号と数値で判断する ／ フラグが付いても、急ぐとは限らない |
| reference | 基準範囲 | 健康な人の大多数がこの中に入る、という範囲 ／ 外れても病気とは限らず、中でも安心とは限らない ／ 索引の項目ごとに載っている |
| recollect | 再採血 | もう一本、採ってもらう ／ 検体側の問題（溶血・凝集・希釈・取り違え）を疑うとき ／ 時間がかかる。パニック値なら先に報告してから |
| rerun | 再検 | 同じ検体をもう一度測る ／ 装置側の問題を疑うとき ／ 検体が悪ければ同じ値が出るだけ。検体の問題は再採血 |
| tourniquet | 駆血・握り込み | 駆血帯を長く締めたり、手を握らせ続けると K が見かけ上上がる ／ 溶血がなくても起きる。医師が「採り直して」と言う理由の一つ ／ 再採血で戻れば採血手技。戻らなければ本物 |
| sample_state | 検体状態 | 受付で見た検体の見た目。溶血・乳び・凝固・量不足 ／ 値を信じていいかを決める、最初の情報 ／ 何もなければ「特記なし」。それも情報 |
| levels | 報告レベル（通常／至急／緊急） | 通常＝カルテへ送る。至急＝担当医へ直接メッセージ。緊急＝電話＋読み返し ／ 全部を緊急にすると、本当に急ぐ連絡が埋もれる ／ レベルを選ぶこと自体が判断 |
| readback | 読み返し確認 | 電話で伝えた値を、相手に復唱してもらう ／ 聞き間違い（6.4 と 4.6）を防ぐ ／ 緊急報告では必ず行う |
| comment | コメント | 報告に添える、検体側の見立て ／ 値だけでは伝わらない「なぜこの報告か」 ／ 画面で選んだマークと疑いから組み立てる。自分で書かない |

### 開き方
**既存の「項目名をタップすると索引が開く」と同じ動き。** 辞典の語に同じ下線を付け、
タップで索引パネルに開く。

タップできる場所：
- 検体状態欄の語（「溶血（2+）」→ hemolysis）
- 疑いタブの6語（suspects.json の id と辞典の id を揃える。real は辞典に持たない）
- フラグ欄の記号（H/L/HH/LL → flags。Δ → delta）
- 前回値の列見出し（→ previous）
- 報告ダイアログのレベル名（→ levels）、コメント欄の見出し（→ comment）
- **ナビ・講評・申し送りの本文中の語**。`aliases` を含めて文字列一致で自動リンク。
  患者情報欄（主訴・既往）は対象外——病名側の言葉に下線を付けない

### 索引パネルの中
上に「項目」「言葉」のタブを二つ。既存の索引は「項目」に入る。
「言葉」は五十音ではなく**上の表の順**（見る順に並んでいる）。

## 2. 組み立て式コメント

### 何を変えるか
報告ダイアログのコメント欄を、**自由記述から候補のタップに変える。** 打つものはゼロ。

候補は、プレイヤーが**もう画面で選んだもの**から組む：

| 出どころ | 候補の文 | 出る条件 |
|---|---|---|
| マーク × 疑い | `{項目}：本物の異常と判断` | real |
| | `{項目}：溶血（{段階}）の影響を疑う` | hemolysis |
| | `{項目}：EDTA凝集の可能性` | clot |
| | `{項目}：点滴側採血の疑い` | dilution |
| | `検体取り違えの疑い（前回値と不一致）` | mismatch（項目は書かない） |
| | `{項目}：前回値から急な変化（{前回}→{今回}）` | delta |
| 検体状態欄 | `検体状態：{欄の内容}` | 欄にコメントがあるとき |
| | `検体状態に特記なし` | 欄が空のとき |
| 再採血の結果 | `再採血で同値（{今回}）` | 二本目があり、前後の差がΔ幅の半分以内 |
| | `再採血で基準範囲内（{今回}）` | 二本目があり、基準範囲に戻った |
| 操作 | `再採血を依頼中` | 報告と一緒に再採血を選んだとき |

- 候補は**マークした項目の順**に並ぶ。マーク0件なら検体状態と操作の候補だけ
- 一〜三行を選ぶ。四行目は選べない（緊急報告に9行並べさせない。症例4と同じ理由）
- 選んだ行がそのまま報告の文面。**電話の読み返し画面にも同じ文が出る**
- 自由記述の欄は消す。残さない（隠すだけにすると、そこに書けることを期待される）

### 形
`data/comment_templates.json`。上の表をそのまま持つ。`{項目}` などは描画時に埋める。
```json
{ "id": "recollect_same", "text": "再採血で同値（{now}）", "when": "recollect_same" }
```
`when` は候補を出す条件の名前。判定は `derive.js` 側の関数（DOM に触らない。テストから呼ぶ）。

### 評価
`choices.when.comment` を広げる。
- `true` … いままでどおり「一行以上選んだ」
- `["recollect_same"]` … 指定した候補が**全部**選ばれていれば一致
- 書かなければ不問

**今回は既存症例の `comment: true` を変えない。**中身で締めるのは、次のどれかを決めてから：
症例7の最善に `["recollect_same"]` を足すのが最初の候補（コメントの中身がその症例の教えたい判断だから）。
症例3・6は `true` のままでよい。

### 電話画面
緊急報告の電話画面は、値の読み返しのあとに**選んだコメントを技師の台詞として読む**。
「K 6.2、再採血で同値です」。一行ずつ。

## 3. 指さし

### 何を変えるか
症例0〜3のナビは、**一文ごとに画面の該当箇所を光らせる。** 台詞は変えない。

`nav` の各文に `focus` を一語足す。
```json
{ "speaker": "kanae", "emotion": "normal", "text": "……", "focus": "sample_state" }
```
`focus` の値（画面の領域の id）：
```
reception      受付一覧
patient        患者情報欄（主訴・バイタル）
results        結果テーブル全体
flags          フラグ欄
sample_state   検体状態欄
previous       前回値の列
messages       院内メッセージ
report         報告ボタン
```
- **一文に一つ。**二つ光らせない。どちらを見ればいいか分からなくなる
- 光り方は**枠が点いて2秒でゆっくり消える**。点滅させない（割り込みの点滅と区別する。
  `prefers-reduced-motion` では即時に消す）
- 症例4以降は `focus` を書かない（結論を言わない段階。書いてあっても無視する）
- `focus` は演出で、判定には一切効かない

### 「見る順番」
索引パネルの「言葉」タブの**いちばん上に固定で一枚**。五行だけ。

```
見る順番
1. 検体状態  …… この検体を信じていいか
2. フラグ    …… 何が基準の外か。HH/LL はあるか
3. 前回値    …… この人にとって変か
4. バイタル  …… 値と矛盾しないか
5. 報告レベル …… 通常か、至急か、電話か
```
各行の語は辞典にリンクする。**答えではなく手順**なので、症例4以降も上級でも消さない
（上級で消すのはナビと索引の「項目」。「言葉」と「見る順番」は残す。roadmap 4章
「調べるのが常に損にならない」と同じ理由）。

### 症例0に足す台詞（ステップは増やさない）

「検体状態欄」のステップ（0-4）の末尾に一行。

**かなえ / normal**
> 「溶血って何」は、その字をタップ。辞典が開く。

**悠介 / normal**
> 分からない言葉は、その語をタップしてください。辞典が開きます。

最後のステップ（0-8・メッセージ欄と報告）の末尾に一行。

**かなえ / normal**
> 迷ったら索引の「見る順番」。上から順に見れば、だいたい着く。

**悠介 / normal**
> 判断に迷ったら、索引の「見る順番」を開いてください。上から順に確認します。

## 4. 実装順

1. `data/glossary.json`（16語）と索引パネルの「言葉」タブ。タップで開く経路
2. 本文の自動リンク（ナビ・講評・申し送り。患者情報欄は除く）
3. `data/comment_templates.json` と候補の生成（`derive.js` 側、DOM に触らない）
4. 報告ダイアログのコメント欄を候補のタップに差し替え。自由記述を消す。電話画面に読ませる
5. `when.comment` の配列対応（既存の `true` は変えない）
6. `nav` の `focus` と光り方。症例0〜3に `focus` を入れる
7. 「見る順番」の一枚と、症例0の四行
8. テスト、docs（design.md・characters.md・roadmap.md・CLAUDE.md）

### テストで固定すること
- 辞典16語が全部三行以内、`lines` に病名（`data/conditions.json` の名前）が含まれない
- `suspects.json` の id（real 以外）が辞典に全部ある
- 候補の生成：マーク×疑いの組み合わせ全部で候補が出る、マーク0件でも検体状態の候補が出る、
  四行目が選べない、`recollect_same` は二本目があるときだけ出る
- `when.comment` が `true` のときは既存の判定が一つも変わらない（n01〜n07 の既存テスト）
- `when.comment` が配列のとき、指定の候補が全部選ばれたときだけ一致
- `focus` の値が上の8つのどれかであること。症例4以降の `nav` に `focus` が無いこと
- 自由記述の `<textarea>` / `<input>` が報告ダイアログに存在しないこと
- 患者情報欄の中に辞典のリンクが一つも無いこと

## 5. やらないこと

- 自由記述の欄を残さない。隠さない。消す
- 辞典に病名を書かない。候補の文にも書かない。「症状」ではなく**検体側の見立て**の言葉だけ
- 辞典の一語を三行より長くしない。長くなるなら逆引き辞典（roadmap 4章）の仕事
- 指さしを二か所同時に光らせない。点滅させない
- 症例4以降に `focus` を書かない。「見る順番」は消さない
- 「見る順番」に症例固有のことを書かない。全症例で同じ五行
- 上級モードの時間コストは今回入れない（逆引きと一緒に、進め方 8）

## 6. 実装との差（2026-09-08 実装時に決めたこと）

### 辞典
- `dilution` の二行目を「全体が薄まり、点滴の中身（**ブドウ糖**）だけ高く見える」にした。
  実務の一般論では生食なら Na も上がるが、ゲーム内の `iv_line_dilution` は全項目 ×0.75 で
  Na も下がり、上がるのは Glu だけ。辞典を読んで画面を見たときに食い違わないほうを採った
- 本文の自動リンクは `kind` が `nav`（ナビ・講評）と `handover`（申し送り）のときだけ。
  医師の返信と受付の記録は相手の言葉なので触らない（仕様の列挙どおり）
- 基準範囲の列見出しもタップできるようにした。仕様の列挙にはないが、前回値の見出しと
  対になる位置にあり、辞典に語がある
- 疑いタブは選ぶボタンなので、辞典へは隣に置いた小さな「?」から開く（ボタンの入れ子は作れない）
- 「見る順番」の「バイタル」だけ辞典に語がないので、そこはリンクにしない

### コメント
- 候補は `text`（報告の文面）に加えて `speech`（電話で読む言い方）を持つ。
  仕様の「K 6.2、再採血で同値です」を電話で出すため
- `{grade}` は「（3+）」の形（括弧ごと）。溶血のない検体では空になり「K：溶血の影響を疑う」になる
- 再採血の候補（`recollect_same` / `recollect_normal`）は項目名を頭に付けた。
  マークが複数あると、項目名がないと同じ文が並んでしまうため
- 前回値のない項目には `delta` の候補を出さない（「（—→6.4）」になるため）
- 「自由記述の `<textarea>` / `<input>` が無いこと」のテストは、`<textarea>` が無いことと、
  `<input>` が報告レベルのラジオと再採血のチェックだけであることに読み替えた
- 差し戻しの二本目を報告するときは、報告ダイアログと電話の受付番号も二本目のものにした

### 指さし
- 「一文ごとに自動で光る」ではなく、**文の末尾の「ここ」を押すと光る**形にした。
  ナビは何度でも読み返せること、順に自動で光らせると「一文に一つ」を守れないこと、
  スマホでは結果画面が別のタブにいて自動では見えないこと、の三つが理由。
  押すとその画面に切り替わってから光る
- `prefers-reduced-motion` では枠が消えるまでの2秒は変えず、フェードだけ止める。
  完全に出さないと、その人だけ指さしが使えなくなるため
- 「見る順番」は「言葉」タブの実装と同じコミットに入れた（順7ではなく順1〜2）

### 症例0の指さし（2026-09-08 追加）

当初は「症例0は台詞がモーダルの中に出るので `focus` を入れない」としていたが、説明モーダルを
**下に寄せた帯**に変えて上半分に画面が見えるようにし、症例0にも指さしを入れた。

- **症例0だけ自動で光らせる。押させない。** まだ何を押せばいいか分かっていない段階なので、
  「ここ」を押させる形（症例1〜3）は使えない。「次へ」で進むたび、そのステップの各文の
  該当箇所が上から順に、一か所ずつ2秒光って消える
- 同じ場所が続く文は `focus` を `null` にする。同じ枠が続けて光ると点滅に見えるため
- **枠は時間で消さない（2026-09-08 変更）。** 次の文に移るまで、最後の文なら「次へ」を押すまで
  出したままにする。初見でも目が行くよう、ナビの枠（濃紺3px）より太い黄色（`--point` 5px）にし、
  現れるときだけ0.3秒で線が引かれる動きを一度。点滅はさせない（受付一覧の割り込みとぶつかる）。
  `prefers-reduced-motion` では動きなしで即座に出す。症例1〜3の「ここ」は2秒で消えるまま
- 枠を出したままにしたので、**続きの文には同じ場所を書く**（同じ場所なら付け直さないので動かない）。
  `null` は「指す先がない」の合図で、そこで枠を消す（索引の話、着任と締めの台詞）。
  一度離れた場所を同じステップで指し直さない——線を引き直すと点滅に見えるため
- **スマホ縦でも自動発火のままにできた。** 指さしが画面を切り替えてから光らせるので、
  結果画面が別タブでも見える。帯の裏に入らないよう、症例0の間だけ送り先を画面の上に寄せ
  （`scroll-padding` と `.cols` の下余白）、帯は高さ46vhに抑えてある
- チュートリアル中の結果画面は**骨組み**にした。欄の位置は本物と同じで、結果と前回値は「―」。
  検査値は一つも出さない（基準範囲は患者の値ではなく当院の規定なので出す）。
