# 所見一覧式コメント（2026-09-08）

`docs/readable.md` 2章「組み立て式コメント」の改訂。読む順は readable.md → これ。

## 背景

通しプレイで症例3（P-0003）に引っかかった。ナビは「小球性低色素性、前回から継続」の一行を
付けろと教えるのに、コメント欄にはその候補がない。いまの候補は「マーク×疑いタブ」「検体状態」
「再採血」「操作」からしか組まれないため、疑いタブにない所見（前回から続いている、小球性）は
言えず、プレイヤーには「選べる文がないのにコメントが欲しかったと言われる」に見える。

自由記述を消した時点で、症例3の教えたいことを言う手段が消えていた。仕様の穴。

## 変えること

コメントの候補を「画面で選んだものから組む」から、**固定の所見一覧から選ぶ**に変える。

- 一覧は**全症例で同じ**。症例ごとに候補を書き足さない（「見る順番」を全症例で同じ五行にしたのと同じ理由）
- 一覧は**常に全部出す**。マークや検体状態で絞らない。毎回同じ一覧を読むこと自体が学習になる
- `{項目}` を持つ文は、**マークした行ごとに展開**する（マーク0件なら項目付きの文は出ない。
  項目なしの文は出る）
- コメントの中身がプレイヤーの判断になる。外れた所見を選んだら、教えたい判断の範囲で指導役が講評する

「候補を出す条件」は**文が成立するか**だけで決める。正しいかどうかは見ない（それは判定の仕事）。
ただし**事実の文だけは事実どおりにしか出さない**（「再採血を依頼中」を依頼していないときに出さない。
嘘の文を選ばせる意味はない）。

## 一覧（`data/comment_templates.json`）

三つの群に分けて出す。群の見出しは固定。

### 値について（`group: "value"`）

| id | text | 展開 | 出る条件 |
|---|---|---|---|
| real | `{item}：本物の異常と判断` | マーク行ごと | マークがある |
| continued | `{item}：前回（{prev}）から継続、急な変化なし` | マーク行ごと | マークがあり、その行に前回値がある |
| delta | `{item}：前回値から急な変化（{prev}→{now}）` | マーク行ごと | 同上 |
| microcytic | `小球性低色素性の像（Hb・MCV・MCH 低値）` | なし | 常に |
| macrocytic | `大球性の像（MCV 高値）` | なし | 常に |
| inflammation | `WBC・CRP 上昇、炎症反応として整合` | なし | 常に |
| renal | `Cre・BUN 上昇、腎機能低下と整合` | なし | 常に |

microcytic 以下の4本は赤血球指数や項目の組み合わせの**読み**であって病名ではない。
病名（鉄欠乏性貧血、腎不全、敗血症）は書かない。増やすときも「どの項目がどう動いているか」の言い方に限る。

### 検体について（`group: "sample"`）

| id | text | 展開 | 出る条件 |
|---|---|---|---|
| hemolysis | `{item}：溶血{grade}の影響を疑う` | マーク行ごと | マークがある |
| clot | `{item}：EDTA凝集の可能性` | マーク行ごと | マークがある |
| dilution | `{item}：点滴側採血の疑い` | マーク行ごと | マークがある |
| mismatch | `検体取り違えの疑い（前回値と不一致）` | なし | 常に |
| sample_state | `検体状態：{sample}` | なし | 検体状態欄にコメントがある（事実） |
| sample_state_clear | `検体状態に特記なし` | なし | 検体状態欄が空（事実） |

`{grade}` は溶血のない検体では空になり「K：溶血の影響を疑う」になる（現状どおり）。

### 操作と再採血（`group: "action"`）

| id | text | 展開 | 出る条件 |
|---|---|---|---|
| recheck | `再採血を依頼中` | なし | 再採血のチェックが入っている（事実） |
| recollect_same | `{item}：再採血で同値（{now}）` | マーク行ごと | 二本目があり、前後の差がΔ幅の半分以内（事実） |
| recollect_normal | `{item}：再採血で基準範囲内（{now}）` | マーク行ごと | 二本目があり、基準範囲に戻った（事実） |

### 候補のID

- 項目付きの文は `templateId:testId`（例 `continued:Hb`）。現状の `${suspectId}:${testId}` と同じ形
- 項目なしの文は `templateId` そのまま

### 並び順と見た目

- 群の順は 値 → 検体 → 操作。群の中は一覧の順、項目付きの文はマークした順
- スマホで長くなるので、群ごとに `<details>` で折る。既定で開くのは「値」だけ。
  一度開いた群はその症例の間は開いたまま
- 選択の上限は3行のまま。上限の表示も現状どおり
- 疑いタブとの関係：疑いタブはそのまま残す（判定の `suspects` はタブを見る）。
  タブで押した疑いと同じ文が一覧にもあるが、**自動では選ばない**。コメントに載せるかは別の判断
  （症例5-bは「本物」＋「溶血」の両方をタブで押すが、電話で読むのは一行でいい）

## 判定（`choices.when.comment`）

いままでの形は全部そのまま動く。

- `true` / `false` … 一行以上選んだか
- `["recollect_same"]` … 配列は `must` の略記
- **新しく** `{ "must": [...], "forbid": [...] }`
  - `must` … 全部選ばれていれば一致
  - `forbid` … 一つでも選ばれていれば不一致
  - IDは `continued` のように素で書けば「どの項目でも」、`continued:Hb` と書けば「その項目で」

`src/report.js` の `matchesComment` を広げる。`commentTemplateIds` は素のIDを返しているので、
`continued:Hb` の照合には選んだ候補の `id` も見る。

## 症例への反映

一覧は固定なので、**外れの所見を選べる症例では、外れ用の枝を best の上に置く**。
講評を書くのは、その症例で教えたい判断に関わる外れだけ。他の外れは医師の返信で軽く受ける。
医師を悪者にしない。

### 汎用の医師返信（新規・2本）

`msg_comment_off`（通常・至急の報告に対して）
> 結果は受け取りました。付記のうち、結果と合わないものが一つあるようです。
> 検査室で一度見直していただけますか。報告レベルはこれで構いません。

`msg_comment_off_emergency`（緊急報告に対して）
> 値は受けました。電話で添えられた所見のうち、こちらの見立てと合わないものがあります。
> 対応はこちらで進めますので、検査室でも確認をお願いします。

## やらないこと

- 病名を一覧に並べない（増やすときも「どの項目がどう動いたか」の言い方だけ）
- 自由記述の欄は作らない
- 一覧を症例ごと・モードごとに変えない。上級モードでも同じ一覧
- 外れの全組み合わせに講評を書かない。教えたい判断に関わるものだけ
- 疑いタブを消さない。タブと一覧を自動で同期させない
- 一覧の文に行動（電話・緊急）を書かない

## 実装との差

### 判定に `any` を足した（症例4の枝のため）

仕様の「候補を出す条件」と「判定」の定義（`must` は全部選ばれていれば一致、`forbid` は一つでも
選ばれていれば不一致）はそのまま実装した。ただし**症例への反映の3か所は、その定義のままでは
逆の枝になる**——書かれている `comment: { "forbid": [...] }` は「それを選んでいないとき」に当たるので、
外れを選んだ人ではなく、正しく選んだ人が拾われてしまう。講評の文面から意図を採って、こう置いた：

| 症例 | 仕様 | 実装 | 理由 |
|---|---|---|---|
| 3 | `forbid: ["delta"]` | `must: ["delta"]` | 「急な変化」を**選んだ**人に講評する |
| 6 | `forbid: ["continued"]` | `must: ["continued"]` | 「前回から継続」を**選んだ**人に講評する |
| 4 | `forbid: ["hemolysis","clot","dilution"]` | `any: ["hemolysis","clot","dilution"]` | 検体側の疑いを**一つでも**選んだ人に講評する |
| 5-b | `must: ["hemolysis"], forbid: ["real"]` | そのまま | 定義どおりで意図と一致する |

症例4の「一つでも」を表すため、`must` / `forbid` に加えて **`any`**（一つでも選ばれていれば一致）を
足した。足したくなければ、同じ枝を三本（`must: ["hemolysis"]` / `["clot"]` / `["dilution"]`）に
割れば `any` なしでも書ける。判定の広げ方はこの3語だけで、ほかは変えていない。

### 汎用の返信を二度届けるための `repeat`

`msg_comment_off` は症例3と症例6の両方で使う。院内メッセージは同じIDを二度積まない作りなので、
そのままだと二度目の症例で医師の返信が届かなかった（実際に症例3→症例6で消えた）。
汎用の2本に `"repeat": true` を付け、届くたびに `msg_comment_off#2` の形の控えで別の便として積む。
中身は同じメッセージを引く。

なお、既存の `msg_n04_urgent_kanae` も症例4と症例5-bの両方から参照されていて同じ制限がある。
今回の範囲ではないので触っていない（両方に当たる遊び方をすると、二度目の講評が出ない）。

### 一覧・文面

- 中身の空の群は見出しごと出さない。「操作と再採血」は再採血のチェックも二本目もないと0件になり、
  空の箱だけが残るため。群の見出しと順番は固定のまま
- `recollect_same` と `recollect_normal` は仕様の表どおり独立に判定する（どちらも成立すれば両方出る）。
  現行の症例では同時に成立しない
- 新しい4本（`microcytic` / `macrocytic` / `inflammation` / `renal`）の `speech`（電話で読む言い方）は
  こちらで書いた。仕様には `text` だけがあったため
- `continued` の `{prev}` は前回値の表示、`{now}` は今回値。`text` は仕様どおり `{prev}` だけを使う

### 症例3のナビ

仕様の一文に差し替えると、かなえの次の行（「一行あるだけで、医者が見る速さが変わるから」）が
「二行」と食い違うので、「その二行があるだけで」に直した。悠介は仕様の一文のうしろに、
既存の「数値だけを送るより、はるかに読まれます」を残している。`dialogue.md` も同じに直した。

### テスト

- 旧い候補の作り方（マーク×疑い）を前提にしていた4本は、所見一覧の形に書き直した
  （一覧が全症例で同じこと・項目付きはマークした行ごとに出ること・事実の文の条件・並び順）
- 「comment を配列で書いている枝はまだ無い」というテストは役目を終えたので、
  「条件は真偽値・配列・`{must, any, forbid}` のどれかで、IDは一覧に実在する」に差し替えた
