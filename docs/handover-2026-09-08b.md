## このスレで見つかった仕様の穴と、その処理

- **症例3で候補がない。** ナビは「前回から継続」を書けと言うのに、コメント候補は疑いタブからしか
  組まれず、その文がなかった。自由記述を消した時点で症例3の教えたいことが言えなくなっていた
  → 所見一覧式に変更。一覧は固定・全症例共通・常に全部出す（統一感を消去法のリスクより優先）
- **「本物の異常」が重さに読める。** 作者本人が押せなかった。タブが聞いているのは「値が患者のものか、
  採血のせいか」であって重さではない。「検体に問題なし」も「体に異常なし」と読み違える
  → 「採血に問題なし（値は患者由来）」。選ぶ根拠は消去法（検体状態が空・関連項目が同じ向き・前回値と矛盾しない）
- **`forbid` の向きを仕様書で間違えた。** 「外れを選んだ人を拾う枝」の条件は `must` であって `forbid` ではない。
  Code が気づいて症例側だけ直し、`any` を足した
- **同じIDのメッセージは二度届かない。** 汎用の医師返信と共用の講評で発覚。`repeat: true` で解決。
  新しい共用メッセージを作るときはこれを付ける
- **マークの上限で弾かれた。** 症例3で L が5行点いていて、全部マークするのは新人として素直。
  「急ぎの1つだけ」は症例4の担当なので、症例3の `max` は外した

## 決まったこと（追加分）

- コメントは所見一覧から選ぶ。一覧は症例ごと・モードごとに変えない。病名は並べない
- 外れた所見への講評は、教えたい判断に関わるものだけ（症例3・4・5-b・6）。他は汎用の医師返信
- 疑い `real` の内部IDは変えない。札とヒントと辞典で意味を伝える
- 音は出来事にだけ付ける。HH・危険域・判定の良し悪しに音を付けない（「HHを見たら電話」の反射を作らない、と同じ線）
- 声・BGM・音声ファイルは作らない。声をやるなら短い決め台詞だけ（未定）
- 指導役の改名（三嶋かなえ→桐谷あすか／早瀬律）は引き続き見送り。方針は前回どおり

## 遊ぶ手順・Code に頼むときの型・絵の作り方

前回の `handover-2026-09-08.md` のまま。追記は二つだけ：

- 仕様書のファイルは GitHub 連携から書けない（403）ので、チャットで作ったものをゆうが `docs/` に置いて push する。
  それから Code に「`docs/xxx.md` を読んで、`main` から新しいブランチで」と頼む
- 仕様書に「外れを拾う枝」を書くときは、条件が `must`（選んでいる）か `forbid`（選んでいない）か、向きを一度声に出して確かめる

リモートに残っていたブランチ5本は手元の `git push origin --delete` で消せる（未確認なら `git branch -r` で見る）。
