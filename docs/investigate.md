# ERLAB 「調べる」の仕様（2026-09-08）

操作四段階 `見つける → 疑う → 調べる → 報告する` の三段目。roadmap §6-3-b。
mechanics.md の続きとして読む。ここで `actions` が確定し、次の判定ルール言語化（§6-4）に進む。

決めたこと（チャット 2026-09-08）：
- 調べた結果は検体状態欄とは**別欄**に出す
- 5-b と 6 の best 条件に行動を足す。行動なしで従来の best を取った操作は **ok に降格**
- 塗抹は血小板・凝集に加えて**赤血球の形（大小不同・破砕）まで**返す
- 電話は点滴・採血に加えて**患者の様子を一言**返す。横の連絡として当然のものは入れる
- 併せて「指導役に聞く」を入れる（§8）。辞典の語を増やす（§9）

## 1. 検体状態欄との住み分け

- **検体状態欄 ＝ 装置と受付が勝手に言ってくること。** 溶血インデックス、量不足。空欄は「装置は何も言っていない」の合図。変えない
- **調べた結果 ＝ 自分で確かめたこと。** 装置が言わないもの（フィブリン、凝集塊、ラベル不一致、点滴の側）と、装置の言い分の裏取り

検体目視の価値は溶血の再確認ではなく、**消去法の根拠を揃えること**。`real`（採血に問題なし）を選ぶ根拠は
「検体状態が空・関連項目が同じ向き・前回値と矛盾しない」の消去法（suspect-real.md）。その消去法を画面に出す操作。
だから正常検体でも目視は空振りにしない。「淡黄色。凝血なし。量十分」と返る。それが `real` を押す根拠になる。

## 2. 行動の一覧

| ID | ボタン表記 | 行動 | 返るもの（三行固定） | 使える条件 |
|---|---|---|---|---|
| `look` | 目視 | 検体を見る | ① 血漿の色（淡黄／淡赤／赤／暗赤） ② 凝血塊・フィブリンの有無 ③ 量 | 常に |
| `idcheck` | ID | ラベルと依頼を照合 | ① ラベルの患者ID・氏名 ② 依頼の患者ID・氏名 ③ 一致／不一致 | 常に |
| `smear` | 塗抹 | 塗抹を作って鏡検 | ① 血小板凝集塊の有無 ② 血小板の見え方（散在・十分／少ない） ③ 赤血球の形（大小不同・破砕の有無）とフィブリン | `order` に CBC があるとき。なければボタンは「血算の依頼なし」で押せない |
| `call` | 電話 | 依頼元へ電話 | ① 点滴の有無と側（左右） ② 採血の状況（誰が・どこから） ③ 患者の様子を一言 | 常に |

方針：
- 返る文は検体側・採血側の事実と、横の連絡として当然の患者の様子まで。病名・身体所見・診断の示唆は返さない
  （roadmap §3 「検査値を見ずに答えが出せる情報は入れない」と同じ線）
- 塗抹の赤血球の形は「見えた形」まで。形から病名は言わない。破砕赤血球は「報告に添える所見であって、原因は検査室で決めない」の位置
- 電話の相手は `patient.from` で自動。ER → 「ER 当直看護師」、病棟 → 「病棟看護師」、外来 → 「外来看護師」
- 各行動は1症例1回。押すと結果が出て、ボタンは「済」に変わる。取り消しはない
- `idcheck` / `smear` / `call` は**一度押したら、検体が変わっても再度はできない**。
  逆に、まだ押していなければ再採血検体（`recollect`）が届いたあとでも押せる
- `look` だけは**検体ごとに1回**。再採血検体が来たらもう一度できる
- 行動の**順番は評価しない**。電話で追加の質問はできない（選択肢を増やすと自由記述に戻る）

## 3. 画面

### 3-1. ボタン
結果テーブルの下、報告ボタンの上に4つ横並び。スマホ縦390pxで一段に収まる短い表記（目視／ID／塗抹／電話）。
押せない状態（塗抹で CBC なし、済）は薄く。

### 3-2. 調べた結果欄
**行動ボタンの直下**（報告ボタンの上）に置く別欄。PC・スマホとも同じ位置。
押したボタンのすぐ下に結果が出るので、何が返ったのかを目で追える。
検体状態欄（装置と受付が言ってくること）には**追記しない**。何も調べていないときは欄ごと出さない。
LIS の記録らしく、時刻と行動名を頭に付けて一行ずつ積む。三行は `／` で繋いで一行に収める。

```
検体状態   溶血（2+）        ← 装置と受付が言ってくること。触らない
（結果テーブル）
［目視］［ID］［塗抹］［電話］  ← 行動ボタン
調べた結果 10:44 目視  血漿は淡赤／凝血・フィブリンなし／量は十分
           10:46 電話  ER：点滴なし／右肘から看護師が採血／ぐったりしているが受け答えはできる
［報告する］
```

時刻は `received_at` から行動ごとに数分進める（見た目だけ。新人モードでは時間の意味を持たせない）。
結果の語（淡赤、凝集塊、フィブリン、大小不同、破砕赤血球、点滴側 など）は下線で「言葉」辞典に飛ぶ（§9）。

**足したばかりの一行**は、その行だけ枠を出して**約1秒でフェードアウト**する。
「いま増えた」の合図であって値の判定ではないので、フラグの黄（`--warn`）・赤（`--panic`）は使わず、
地の濃色（`--head`）の枠だけにする。色だけに頼らないよう、**行頭に「新」の札**を一緒に出し、
枠と同時に消す（`prefers-reduced-motion` では枠を出さず、札だけで見せる）。演出であって、判定には効かない。

**欄が画面の外にあるときだけ寄せる**（`pointFitsBand` を指さしと共用）。見えているときは動かさない。

### 3-3. 指さし
症例5の nav に `focus: "investigate"`（行動ボタンの領域）を一文だけ足す。症例4以降は書かない、という readable.md の
ルールの例外。初出の操作は場所を教える（マークのときと同じ扱い）。

  - `msg_call_default_opd`：点滴なし／看護師が採血／待合で待っている

### 4-2. 症例側の上書き
症例に `investigate` を書いたときだけ既定を差し替える。値は三行の配列か、メッセージID。

```json
"investigate": {
  "call": "msg_n05b_call",
  "idcheck": { "match": false, "label": { "id": "P-0009", "name": "患者G" } },
  "smear": ["凝集塊なし", "血小板は散在・十分", "大小不同あり"]
}
```

`idcheck.match: false` のとき、①にラベルの ID・氏名、②に依頼の ID・氏名、③に「**不一致**」が出る。

### 4-3. 判定
`choices.when` に `actions` を足す。`marks` と同じ形。**書かなければ不問。**

```json
"when": { "report": "emergency", "actions": { "must": ["call"] } }
```

- `must` … 含まれていなければ不一致
- `forbid` … 含まれていたら不一致（「していない人を拾う枝」は `forbid` ではなく、その行動を `must` に書かない枝で受ける。向きに注意）
- `max` … 行動数の上限。上級で「全部押して時間を使いすぎ」を拾う枝用。新人では使わない

`ask`（§8）は `actions` には含めない。別扱い。

## 6. 症例0の追加ステップ（マーク・疑いのステップの後、報告のステップの前）

指さしは一文目で行動ボタン（`investigate`）、三文目で上のバー右端の「聞く」（`ask`）。
二文目（下線の言葉）は画面のあちこちにあるので指す先を決めず、枠を消す（`null`）。

handover の宿題「下線の言葉は全部タップで引ける。引いて減点はない」もここで言う。

**かなえ / normal**
> それと、下の四つ。目視、ID、塗抹、電話。自分で確かめる用。装置が言わないことは、これで見る。
> あと、下線の言葉は全部タップで引ける。分からなかったら引く。引いて減点はない。分からないまま押すほうが減る。
> それでも詰まったら、私に聞いて。ただし聞いた分は評価に出る。

**悠介 / normal**
> 結果の下に四つのボタンがあります。検体目視、ID照合、塗抹、依頼元への電話。装置が検知しないことを自分で確かめる操作です。
> 下線のある言葉はすべてタップで辞典が開きます。引くことで減点はありません。分からないまま進めるほうが失点します。
> それでも判断がつかないときは私に聞いてください。ただし、聞いた場合は評価が許容どまりになります。

## 8. 指導役に聞く（`ask`）

難しい言葉が増えるので、詰まったときの逃げ道を作る。
「訳が分からないときは、減点を受け入れてベテランに聞く」を正規の操作にする。

### 操作
- **上のバー（ヘッダー）の右端**、指導役ボタンの隣に「聞く」。1症例1回
- **位置は症例・モードによらず固定。**ナビ枠が出ていないときも出す（詰まったときの逃げ道を探させない）
- 押すと指導役がその症例の**見どころ**を言う（答えは言わない。「まず検体状態。次に前回値。それから関連項目」の順で、どこを見るかを指す）
- 押したら文字が「聞いた」に変わって押せなくなる。色だけで済ませない
- 指導役がいない日（上級モード、症例が `mentor: false` を書いた日）は、押すと
  「今日は指導役がいません。自分で判断してください。」の一文が出る。文面は `data/messages` に
  共通メッセージ `msg_ask_no_mentor` として持つ（`repeat: true`）

### 評価
`actions` には含めない。**聞いた症例の最終評価は上限 ok**（`cap` と同じ仕組みを使う。既定の cap を `ok` に落とす）。
枝を書き換えなくて済むよう、エンジン側で min を取る。判定画面の見出しの下に一行「指導役に聞いたため、許容どまりです」。
押す前にも、ボタンの `title` / `aria-label` で「1症例1回。聞くと評価は許容どまりになります」と言っておく（隠して減点しない）。

**指導役がいない日に押したときは、上限を落とさない。**聞けていないので減点する理由がない。
評価が見るのは「押したか」ではなく「指導役が答えたか」。

### 台詞
- 手書き症例：`ask: ["msg_nXX_ask_kanae", "msg_nXX_ask_yusuke"]` を症例に持つ。書く量は症例ごとに2本
- 書いていない症例、および生成症例：既定の「見る順番」（`glossary.json` の五行）をその指導役の言い方で出す。
  逆引き辞典（roadmap §4）ができたら、マーク済み or フラグ最上位の項目の逆引き一項目に差し替える。
  **生成症例に台詞を書かない**方針はこれで守れる

### 症例5の `ask`（初出の例。他の症例はこの型で書く）

**かなえ / normal**
> 検体状態、見た？　そこに答えの半分がある。
> それで足りなきゃ、Kと一緒に動く項目を見る。LDとAST。ALTが動いてなければ、指紋。

**悠介 / normal**
> まず検体状態欄を確認してください。そこに判断の半分があります。
> 次に、K と一緒に動く項目、LD と AST を見てください。ALT が動いていなければ、それが溶血の指紋です。

## 9. 辞典に足す語（`data/glossary.json`、一語三行）

調べた結果と塗抹で出る語。下線から引ける。

| 語 | 三行 |
|---|---|
| 塗抹 | 血液をスライドガラスに薄く伸ばして染めたもの。／装置が数えた血球を目で確かめる。／凝集塊や血球の形はここでしか分からない。 |
| 鏡検 | 顕微鏡で見ること。／塗抹標本を見て、装置の数字の裏を取る。／時間はかかるが、装置が言わないことが分かる。 |
| 淡黄色 | 正常な血漿・血清の色。麦茶より薄い。／この色なら溶血の心配はまずない。／これが「採血に問題なし」の根拠のひとつ。 |
| 溶血の色 | 赤血球が壊れてヘモグロビンが漏れると血漿が赤くなる。／薄い赤で（+）〜（2+）、はっきり赤で（3+）相当。／赤いほど K・LD・AST が持ち上がる。 |
| 凝血塊 | 採血後に固まった血の塊。／抗凝固剤との混和不足で起きる。／血小板が消費されて偽性低値になる。 |
| フィブリン | 血液が固まるときにできる糸状のたんぱく。／小さな片が検体に混じると血小板が偽性低値になる。／目視で白い糸や膜に見える。 |
| 血小板凝集塊 | 血小板同士がくっついた塊。／EDTA で起きることがあり、装置が数えられず偽性減少になる。／塗抹で確認し、クエン酸管で採り直す。 |
| 散在 | 塗抹で血小板がばらばらに散っている状態。／凝集していない証拠。／この状態で数が少なければ、本物の減少を考える。 |
| 大小不同 | 赤血球の大きさがそろっていない状態。／鉄欠乏や混合型の貧血で見られる。／MCV が正常でも中身がばらけていることがある。 |
| 破砕赤血球 | ちぎれた形の赤血球。／細い血管の中で機械的に壊れると出る。／報告に添える所見であって、原因は検査室で決めない。 |

## 11. 次の症例（3-c として roadmap §6 に足す）

`idcheck` の不一致が本領を出す症例は今回は作らず、器だけ入れる。
ただし `actions` の確定を判定ルール言語化（§6-4）の前に置く以上、**不一致の症例を一本手書きしてから §6-4 に進む**。

**7-b. 取り違え** の骨子（詳細は次の仕様書）：
- 病棟からの CBC＋生化学。前回値と全体に合わない（Hb も K も Cre も向きがばらばら）
- 検体状態は空。目視も正常。`delta` だけ選ぶと ok どまり
- ID照合で不一致（ラベルは同室の別患者）。best は `mismatch` ＋ `actions.must: ["idcheck"]` ＋再採血
- 教えたい型：値が全部ずれているときは「患者の変化」より先に「同じ人か」を疑う

> **2026-09-09 追記：実装済み（docs/case07b.md）。** 骨子のうち「ID照合で不一致」だけ変えた。
> ラベルの取り違えは受付のバーコード照合で止まるので、検査室まで来る取り違えは
> **ラベルは正しく、中の血が別人**。`idcheck` は一致で返り、best の条件には入るが答えはそこにない。
> 決め手は **MCV（数日では動かない）** と **依頼元への電話**で、best は
> `actions.must: ["idcheck", "call"]`。`actions` の「押せば正解」ではない使い方がここで確定した。
