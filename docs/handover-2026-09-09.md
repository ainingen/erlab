## 判断したことと、その理由

### 調べる・聞く

| 判断 | 理由 |
|---|---|
| 調べた結果は**検体状態欄と別欄**に積む | 検体状態欄＝装置と受付が勝手に言ってくること。調べた結果＝自分で確かめたこと。混ぜると「装置が言った」のか「自分が見た」のか区別がつかなくなる |
| 正常検体の目視も**空振りにしない**（淡黄色／凝血なし／量十分） | `real`（採血に問題なし）は消去法で選ぶもの。その根拠を画面に出す操作が目視（investigate.md §1） |
| 電話は**調べた結果欄に短い一行、院内メッセージに看護師の言葉**の二本立て | 欄はLISの記録らしく詰めたい。台詞は台詞として読ませたい。両方を一か所に入れると、どちらも中途半端になる |
| `actions.forbid` は「**その行動をした人を弾く**」向き | 前スレの `comment` で一度間違えた向き。「していない人を拾う枝」は `must` を書かない枝で受ける。コメントとテストの両方に残した |
| 「1症例1回」＝**済んだ行動の再実行だけを潰す** | 一本目で電話していない人が二本目で電話できないのはおかしい。§2 と §12 の文がどちらにも読めたので、文ごと直した |
| 「点滴側採血」を**希釈の別名から独立**させた | 希釈＝値がどう動くか、点滴側採血＝何をしたか。調べた結果から引きたいのは後者 |
| `ask` の上限は**エンジン側で min を取る**（`cap` を ok に落とす） | 症例側の枝を書き換えずに済む。枝の数は増やさない |
| `ask` の既定の台詞は**「見る順番」から組む** | 生成症例に台詞を書かない方針を守れる。順番を直せば台詞も一緒に直る |
| 「聞く」を**上のバー右端**に置いた | 詰まったときに押すものなので、そのつど場所を探させない。症例・モード・ナビ枠の有無によらず位置を固定した |
| 指導役がいない日は**上限を落とさない** | 聞けていないので減点する理由がない。評価が見るのは「押したか」ではなく「**指導役が答えたか**」 |

### 画面（貼り付けと欄の位置）

| 判断 | 理由 |
|---|---|
| 指さしは**画面の外のときだけ寄せる** | すでに見えているものを動かすと、読んでいる途中で画面が飛ぶ。帯の上は貼り付いたバーの下、下は症例0の説明モーダルの上 |
| 上のバーを**貼り付けた**（sticky・390pxで46px） | 「聞く」は困ったときに押すもので、どこまで下に読んでいても見えているべき。ついでに結果表が先頭で 5行 → 7行に増えた |
| **タブもバーと一枚の包みで**貼り付けた | 別々に貼ると間に隙間ができて、そこから本文が透けた。逃げ幅（`--headbar`）もタブぶん広げた |
| 調べた結果欄を**行動ボタンの直下**に移した | 結果テーブルの下だと、押したボタンと結果が離れていて何が返ったのか分からない。押した場所のすぐ下に出れば目で追える |
| 増えた一行の合図は**地の濃色の枠＋「新」の札**、1秒で消す | 「いま増えた」の合図であって値の判定ではないので、フラグの黄・赤は使わない。色だけに頼らないよう札を併せ、`prefers-reduced-motion` では札だけにする |

| 判断 | 理由 |

### 判定ルール（roadmap §6-4）

| 判断 | 理由 |
|---|---|
| 規則は **事実 → 正解の操作 → ずれ** の三段で書く | 「この操作なら best」を並べると症例の数だけ表が要る。事実から正解を導けば、生成症例にもそのまま効く |
| **手書き症例の判定は一切変えない。** `choices` の無い症例だけ規則を通す | 規則が手書きを置き換えるのではなく、**手書きから抽出したものが規則**。手書きは型の記録として残す |
| しきい値もコメントの条件表も **`data/judge.json`** に出す | コードに数字を埋めると、線を引き直すたびに実装を触ることになる |
| 突き合わせは **枝ごとの見本だけでなく総当たりでも**数える | 見本は「その枝に落ちる最小の操作」なので、これだけ見ると規則の粗さが出ない。実際、見本 100% でも総当たりでは 91.3% だった |
| 食い違いは **「規則が緩い側（規則のほうが良い評価）」をゼロにする**まで直した | 厳しい側は生成症例で損をしない（best を取り逃すだけ）。緩い側は危ない操作を通すので残せない |
| `real` のコメント条件を「A なし」から **「A なし、または X」**にした | 症例5-b は溶血2+（A あり）で `real`＋`hemolysis` を両方選ぶのが best。「A なし」だけだと 5-b の best 自体が減点される |
| 講評36本と医師返事の共通化は **この段階でやらない** | 見出しのテンプレまでで止め、台詞は次の仕事にした。ここまで混ぜると規則の正しさが台詞の出来で見えなくなる |

## 決まったこと（追加分）

- 症例に `investigate` / `actions` / `ask` を書かなければ、調べるも聞くも既定で動く。既存の枝はそのまま
- 調べた結果は検体状態欄に追記しない。何も調べていないときは欄ごと出さない。位置は行動ボタンの直下
- 電話で返るのは検体側・採血側の事実と、横の連絡として当然の患者の様子まで。病名・身体所見・診断の示唆は返さない
- 塗抹は「見えた形」まで。芽球・異型リンパのような病名に繋がる読みは返さない
- 「聞く」は上のバー右端に固定。押す前に「1症例1回。聞くと評価は許容どまりになります」と言っておく（隠して減点しない）
- 指さしは画面の外にある的だけ寄せる。上のバーの中の的は寄せない（バーごと見えている）
- 上のバーはスマホ縦で一段（48px以内）。タブも同じ包みで貼り付ける。割り込み中はさらに集計と題字を落とす
- 色ルールの例外は5つ（マークの反転／割り込みの赤／指さしの黄枠／報告して閉じた検体の灰／増えた行の枠）。
  どれも値の判定ではなく、必ず文字・記号を併せて出す
- `when.report` は配列で「そのどれか」を書ける。二つ以上のときだけ使う（一つなら文字列）
- MCV は数日では動かない。`real` / `delta` と `mismatch` を分ける材料のひとつ（suspect-real.md）
- 再採血検体（`recollect`）は `seed` で根っこごと差し替えられる。書かなければ一本目と同じ
- `readable.md` の「16語」など、**その日の仕様書に書いた数字は記録として残す**。直すのは
  `characters.md`・`design.md`・`roadmap.md` のような**いまの状態を書いている文書だけ**
- 判定は二本立て。**`choices` を持つ症例は `choices`、持たない症例は規則**（`src/judge.js`）
- 規則のしきい値・検体トラブルの段・コメントの条件表は `data/judge.json`。コードに数字を書かない
- 規則と手書きの食い違いは、**規則が厳しい側だけ許す**。緩い側（規則のほうが良い評価）は残さない
- `choices-table.md` は手で書き足さない。`evaluate()` を通し直して作り直す

## 残していること

**1. 講評の共通化**（judge-rules.md §4。**次はここ**）
規則は見出しのテンプレまでで止めてある。ここから先は台詞。
- **ずれ18種 × 指導役2人 ＝ 36本。** 生成症例には症例ごとの台詞を書かない方針（design.md）なので、
  ずれの種類ごとに1組ずつ持つ。手書き症例は今までどおり症例固有の講評のまま
- **医師の返事は「報告レベル × 正解レベル」の表**にする。いまは症例ごとに `doctor` を持っていて、
  生成症例では引くものが無い。既存の返信を共通化して表に整理する
- `judge()` は `deviation`（`P1`〜`O11`）と `key` を返すので、そこから引ける形にする

**2. シフト制と信頼度**（roadmap.md 1章・進め方 5）
1周＝一晩のシフト。出勤 → 症例が数件 → 退勤で集計。医師の信頼度が一定に達すると
「今日は三嶋さん休みです」の一晩が来る、が本当のクリア。
**未決は計算式・1シフトの症例数・信頼度が落ちたときの扱い。**
`roadmap.md` の「症例を50個作ってから『実はシフト制でした』にならないよう、5を6より先にやる」を守る。

**3. 上級の時間コスト**（roadmap 進め方 8・investigate.md §7）
目視1分／ID照合1分／電話3分（ERは折り返しで5分）／塗抹10分。新人モードは無料のまま。
辞典と同じ「読むか読まないか」ではなく「今やるか、後でやるか」の設計。調べることが常に損にならない線は守る。

**4. 「聞く」の既定を逆引き辞典に差し替える**（roadmap 4章）
いまは索引の「見る順番」の五行を指導役の言い方で出している。逆引き辞典ができたら、
マーク済み or フラグ最上位の項目の逆引き一項目に差し替える。生成症例に台詞を書かない方針はそのまま。

**5. PLiCy のサムネイル**（未着手・仕様未定）
出すときに要る。絵柄の方針（characters.md）に合わせて、低彩度・細い線・写実にしない。
検査値の画面をそのまま出すのか、立ち絵を入れるのか、題字だけにするのかは未定。
**サイズと枚数の規定を PLiCy 側で確認してから決める。** 1ファイル結合（roadmap 9）と同じタイミングで片付ける。

**6. 古い数字は記録として残す**（方針。作業ではない）
`readable.md`・`suspect-real.md`・`investigate.md` などの**その日の仕様書**に書いた語数・件数は直さない。
書いた時点の記録なので、あとから合わせると「いつ何を決めたか」が読めなくなる。
直すのは `characters.md`・`design.md`・`roadmap.md`・`CLAUDE.md` のような、いまの状態を書いている文書だけ。

**7. 判定ルールの既知の残差**（judge-rules.md §11。放置と決めた）
手書きの best が「フラグの点いていない項目まで一緒にマークした」「事実に合わないコメントを付けた」を
見ていないため、規則のほうが厳しくなる枝が104件ある。**生成症例は `choices` を持たず規則だけで判定するので影響しない。**
手書きを規則に合わせて締め直すのは、遊んでいて気になったときでよい。
