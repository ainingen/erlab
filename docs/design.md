# ERLAB 設計メモ

最終更新: 2026-09-07

## 1. コンセプト

- 舞台は救急外来に隣接する臨床検査室。プレイヤーは臨床検査技師。
- **医師パートは作らない。** 病名・治療・薬・画像診断を持ち込むと医学データが爆発するため、検査室に特化する。
- プレイヤーは病名を当てなくてよい。判断するのは以下だけ。
  1. 数字のどこが異常か
  2. その異常は本物か（検体不良・前回値との乖離・矛盾）
  3. 再検・再採血が必要か
  4. どのレベルで報告するか（通常／至急／緊急）
- 「遊んでいたら検査値に強くなっていた」を狙う。ただし医学教育教材は名乗らない。

## 2. 世界観・リアリティの方針

### リアルに寄せる部分（公開資料で固める）
- 基準範囲、H/L/HH/LLフラグ
- パニック値（緊急異常値）の閾値
- 検体トラブルの影響
  - 溶血 → K・LD・AST 上昇
  - フィブリン析出・EDTA凝集 → 偽性血小板減少
  - 採血管間違い（EDTA混入でK↑Ca↓ など）
  - 検体量不足 → 測定不可・希釈
  - 点滴側採血 → 希釈・ブドウ糖↑
- 前回値との比較（デルタチェック）
- 報告フロー（通常＝結果送信／至急＝担当医へメッセージ／緊急＝電話＋読み返し確認）
- 装置ごとのTATの「比率」（血算 数分、生化学 30〜60分、血液ガス 即時、血液培養 日単位）

### 意図的に割り切る部分
- 基準範囲・パニック値は施設差がある → **「架空の病院の運用規定」として1セットに固定**し、出典をdocsに残す
- 時間は圧縮する（TATの比率は維持、絶対値は短縮）
- 「報告が遅れて急変」は演出。因果を強すぎにせず、経過は確率的に扱う
- トリアージ（患者を誰に診せるか）は看護師・医師の役割なので、検査技師にはやらせない。代わりに「報告レベルの選択」がその判断を担う

### 出典の扱い
- 基準範囲・パニック値・検体トラブルの影響量は `docs/sources.md` に出典（学会ガイドライン、検査会社の検査案内など）を記録する
- 将来、医師に「医者が見て笑うレベルの間違いがないか」だけ見てもらう可能性があるため、根拠は追える形で残す

## 3. 画面構成（3つだけ）

すべてテキストとテーブル。グラフィック素材は不要。実際の検査室がPC画面（LIS）を見て仕事をしている世界なので、PC画面を模すこと自体が再現になる。

### 3-1. LIS（検査情報システム）結果画面
- 表形式: 項目名 / 結果値 / 単位 / 基準範囲 / フラグ / **前回値**
- 異常は色ではなくフラグ記号（H, L, HH, LL）で表す
- 検体状態欄にコメントが入る（「溶血（+）」「フィブリン析出」「量不足」など）。見落とすと騙される
- 項目名タップで索引（用語集）パネルが開く

### 3-2. 装置モニタ／受付一覧
- 受付番号 / 患者ID / 依頼元 / 依頼項目 / 状態（受付・測定中・完了・再検）
- ER検体は「至急」マークで上に並ぶ
- 新人モードでは時間無制限なので、キュー管理・優先順位はまだゲーム性にしない（上級で解禁）

### 3-3. 院内メッセージ（グループウェア風）
- シフト開始時に「前シフトからの申し送り」が届く
  - 例: 「患者Bは輸血後なのでHbが動きます」「装置2は校正中で30分使えません」
- 新人モードの解説メールも同じ枡で出す（別UIを作らない）
- 医師からの返信もここに来る（「重症感染症を疑い治療開始」など、プレイヤーが後から学べる情報）
- ストーリー・フレーバーはここに乗せる

### 報告操作
| レベル | 操作 | 使い方 |
|---|---|---|
| 通常報告 | 結果送信ボタン | 電子カルテに結果を送る |
| 至急報告 | 担当医宛メッセージ | 担当医・ERへ直接連絡。コメントを付けられる |
| 緊急報告 | 電話画面 → 読み返し確認をタップ | パニック値。救急担当・上級医へ即時連絡 |

- 評価は「必要十分な判断で正解に到達したか」。全部緊急報告は減点（医師の信頼が落ちる）。パニック値を通常報告にすると患者経過が悪化しうる。

## 4. 新人研修モード（最初に作るもの）

- **時間無制限**
- 軽い患者から
- 索引（用語集）が常時開ける
- 横にナビが出て、異常値の意味と推奨される報告レベルを説明する
- 上級になるとナビと索引を外す。ここまで来ると成長＝上達になる

### 索引の型（全項目この5枠で固定）
1. 何を測っているか
2. 基準範囲（この病院の規定）
3. 高いと何が考えられるか
4. 低いと何が考えられるか
5. 検体トラブルで偽の値が出る条件

### 段階設計（最初の6〜8症例）
1. 全項目正常。「異常なし・通常報告」を選ぶだけ。フラグの見方と送信操作を覚える
2. 1項目だけ軽度H（CRP 2.5 など）。通常報告でよいことを覚える
3. 中等度異常（Hb 9台の貧血）。急がないが「コメント付きで送る」判断
4. 初めてのパニック値（K 6.8、溶血なし）。緊急報告の手順（電話→読み返し）を覚える
5. 同じK 6.8、でも溶血（+）。**「即報告が正解ではない」**を初めて体験。選択肢: ①そのまま即報告 ②溶血ありと付記して報告 ③再採血依頼
6. 前回値との乖離（Hb 13.5 → 9.8）。デルタチェック、再検、患者確認

ここまでで検査室の判断の型がほぼ出揃う。以降は型の組み合わせと項目の入れ替え。

## 5. データ設計

### ファイル分離（すべてJSON）
- `data/tests.json` — 検査項目（名称、単位、基準範囲、パニック値、索引5枠、桁数）
- `data/conditions.json` — 病態テンプレート（根っこの値の範囲と関係性）
- `data/artifacts.json` — 検体トラブル（種類、影響する項目と加算・乗算ルール、検体コメント文）
- `data/hospital.json` — 架空病院の運用規定（基準範囲セット、パニック値、報告ルール、TAT）
- `data/cases/*.json` — 症例（新人モードは手書きで固定。生成器はその後）
- `data/messages/*.json` — 申し送り・解説・医師返信の文面

### 数値のリアリティ確保：根っこの値だけ生成し、派生値は計算する
手作業で全項目を書くと必ず矛盾する。計算で担保する。
- RBC・MCV・MCH を決める → Hb・Ht を導出（Ht = RBC × MCV、Hb = RBC × MCH）
- Na・Cl・HCO3 を決める → アニオンギャップを導出
- 溶血フラグ → K・LD・AST に規定量を加算
- 希釈フラグ → 全項目を一定比率で下げ、Gluのみ上げる
- 派生ルールは `src/derive.js` に集約し、テストを書く

### 症例の構造（案）
```json
{
  "id": "n01",
  "mode": "rookie",
  "patient": { "id": "P-0001", "age": 34, "sex": "F", "from": "ER" },

  "order": ["CBC", "CHEM_BASIC"],
  "seed": { "condition": "normal", "severity": 0 },
  "artifact": null,
  "previous": null,
  "correct": { "report": "routine", "recheck": false },
  "nav": "msg_n01_nav",
  "outcome": { "routine": "msg_n01_ok" }

```

## 6. 技術方針

- 単一HTML（index.html）＋ `src/*.js` ＋ `data/*.json`。開発中は素のES modulesでよい。PLiCyに出すときは1ファイルに結合
- 依存ライブラリなし、または最小
- セーブはlocalStorage（PLiCy上では使用可）
- スマホ縦画面でも表が崩れないこと（PLiCyはスマホ利用が多い）
- フォントは等幅を基本にし、LISっぽさを出す

## 7. 最初のマイルストーン

1. `data/tests.json` に血算・生化学の基本20項目（索引5枠込み）
2. `src/derive.js` に派生値計算＋溶血・希釈の加算ルール＋テスト
3. `data/hospital.json` に基準範囲・パニック値1セット（出典は `docs/sources.md`）
4. 新人モードの症例1〜3をJSONで手書き
5. LIS画面・院内メッセージ画面・報告ダイアログを持つ index.html
6. 画面で見て「検査室っぽいか」を確認 → 方向修正 → 症例4〜6

## 8. やらないこと（非目標）

- 医師視点のプレイ、病名確定、治療選択
- 疾患500種類のデータベース
- 画像検査（CT/MRI/X線）
- リアルタイムの時間制限（新人モードでは）
- 実在施設の基準値の再現
