# ERLAB 講評の共通化（2026-09-09）

judge-rules.md §4 の続き。`choices` の無い症例（生成症例）で、報告のあとに届く三つ——
**見出し → 指導役の講評 → 医師の返事**——を、症例ごとに書かずに済む形にする。
手書き症例（n01〜n07b）の講評と医師返事は一切触らない。

材料は judge-rules.md §3（ずれ P1〜P8・O1〜O11）と `data/messages/rookie.json` の既存の台詞。
共通の台詞は既存の台詞から型を取り出して書き、症例固有の数字・病名・患者名は置き場所（プレースホルダ）にする。

---

## 0. 結論

- 指導役の講評は **ずれ19種（poor 8＋ok 11）＋best 1＝20種 × 2人 ＝ 40本**。1本は2〜3行
- 医師の返事は **正解レベル5行 × 届き方の列** の表で **22本**。O1 のときだけ既存の `msg_comment_off` 系で上書き
- 台詞の中の症例固有の情報は `{key}` `{value}` `{prev}` `{action}` `{level}` の5つだけ。**病名・患者名・症例番号は書かない**
- 置き場所は `data/messages/common.json`。組み立ては `src/review.js` の純関数。`report.js` は `choices` の無い症例のときだけそれを呼ぶ
- 生成症例を1本（`data/cases/g01.json`。`choices` 無し）を一覧の最後に足して、通しで遊べるようにする

---

## 1. 流れ（生成症例のとき）

```
報告 → judge(facts, operation)
       → { score, deviation, headline, key }
     → buildReview(judgeResult, caseDef, operation, context)
       → { headline, reply: [msg_rv_{dev}_kanae, msg_rv_{dev}_yusuke], doctor: msg_dr_{row}_{col} }
     → 既存の「（あれば）指導役の講評 → 医師の返信」の順で表示
```

- `headline` は judge-rules.md §3 のテンプレのまま（既存。`{key}` `{行動名}` は本仕様の `{key}` `{action}` に統一する）
- `reply` は選択中の指導役のぶんだけ表示（既存の `speaker` の仕組み）。指導役がいない日（`mentor: false`）は `reply` を出さない
- `doctor` は必ず1本（characters.md の決まり）
- 「聞く」の cap、差し戻しの cap は変えない（judge-rules.md §3 のとおり）

---

## 2. プレースホルダ

台詞の中で使えるのはこの5つだけ。エンジンが埋める。

| 記号 | 中身 | 出どころ |
|---|---|---|
| `{key}` | 鍵の項目名（K、Hb、MCV…） | `judge().key` |
| `{value}` | `{key}` の今回値（結果表の表示と同じ書式・単位なし） | 結果表 |
| `{prev}` | `{key}` の前回値。**前回値が無い症例では `{prev}` を含む台詞を使わない**（§4 で D・M・R のずれにだけ置く。D・M・R は前回値が無ければ立たない） | 結果表 |
| `{action}` | 欠けた行動の名前。「電話」「ID照合」「目視」「塗抹」（`investigate.md` のボタン名と同じ語） | `judge()`（O4 のとき） |
| `{level}` | 報告したレベルの日本語。「通常」「至急」「緊急」 | 操作 |

- 埋め残しがあったら表示しない（テストで落とす。§7）
- `{value}` `{prev}` の書式は結果表の関数を使い回す。桁を台詞側で決めない
- 手書き症例の `headline` に残っている `{行動名}` は `{action}` に読み替える（データは直さない。読む側で両方受ける）

## 3. 講評の書き方（守ること）

- **数字は `{value}` `{prev}` だけ。** 「三日で」「16 動く」のような症例固有の数を書かない
- **病名を書かない。** 辞典・電話・塗抹と同じ線。「高カリウム血症」「出血」「腎機能障害」は手書きの講評には出るが、共通の講評には出さない。
  言えるのは「パニック値」「変化」「別人」「検体トラブル」まで
- **患者名・症例番号・「前の症例」を書かない。** 生成症例には前後関係が無い
- **1本は2〜3行。** かなえは短く、悠介は教科書的に。design.md／characters.md の人物設定のまま
- **同じことを二人で言う。** 言い方が違うだけで、指摘する内容と向きは同じ
- 危ない向き（P1・P3・P4・P7）はかなえ `serious`／`alert`、悠介 `serious`／`alert`。
  呆れ・言いにくい向き（P2・P5・P6・P8）はかなえ `deadpan`、悠介 `troubled`。ok は `normal`。best は `praise`
- `subject` は全部「報告のあとで」、`time` は「—」、`kind` は `nav`、`repeat: true`（症例をまたいで届く）

## 5. 医師の返事（22本）

### 5-1. 表の軸

**行＝正解レベル**（judge-rules.md §2 の型から）：

| 行 | 型 | 中身 |
|---|---|---|
| `routine` | T1・T2 | 通常報告 |
| `urgent` | T6・T5b | 至急 |
| `emergency` | T3・T5 | 緊急 |
| `hold_sample` | T4 | 値を出さない（検体トラブル）。再採血で止める |
| `hold_mismatch` | T7 | 値を出さない（別人）。取り違えを伝えて再採血 |

T8（差し戻し後）は生成症例に無いので表に置かない（`then` を持つのは手書きだけ）。

**列＝届き方**。`routine`〜`emergency` の3行は報告レベルそのままの4列：

| 列 | 中身 |
|---|---|
| `routine` | 通常報告で値を出した |
| `urgent` | 至急で値を出した |
| `emergency` | 緊急で値を出した |
| `recheck` | 通常＋再採血（＝再採血の依頼だけが届き、値は出ていない） |

`hold_*` の2行は「値が止まったか」「止める旨が届いたか」で5列。
**`note`＝付けたコメントに検体トラブル系（`hemolysis` `clot` `dilution` `sample_state`）か `mismatch` が含まれる**（`data/judge.json` の `comment_rules` で `facts: [A]` か `[M]` を持つコメント。judge-rules.md §8 の P4 の「止めた」と同じ定義）。

| 列 | 条件 | 中身 |
|---|---|---|
| `stopped` | 再採血あり かつ（通常 または note） | 値は止まった。依頼（と一報）が届いた |
| `note_only` | note あり、再採血なし | 値は出たが、検体・取り違えの旨も届いた |
| `leak_recheck` | note なし、再採血あり、至急か緊急 | 値が届いたあとに再採血の依頼が来た |
| `leak_silent` | note なし、再採血なし、通常 | 何も言わずに流れてきた |
| `leak_loud` | note なし、再採血なし、至急か緊急 | 何も言わずに急ぎで届いた |

（`hold_*` 行の「通常＋再採血＋note なし」は `stopped`。T4 の best がこれ）

### 5-2. O1 のときの上書き

`deviation` が O1 のときは表を引かず、既存の `msg_comment_off`（通常・至急）／`msg_comment_off_emergency`（緊急）を使う。両方とも既に共通文で `repeat: true`。

### 5-3. 差出人・件名・時刻

- **`from`** は症例の `patient.from` から組む：「ER」を含む → `ER 当直医`。それ以外は末尾の「病棟」「外来」を落として ` 担当医`（「消化器内科病棟」→「消化器内科 担当医」、「内科外来」→「内科 担当医」）
- **`subject`** は届き方で決める：通常 → `Re: 検査結果（{patient.id}）`、至急 → `Re: 至急連絡（…）`、緊急 → `Re: 緊急報告（…）`、再採血だけ → `Re: 再採血の依頼（…）`
- **`time`** は受付時刻からの経過で決める。値が正しく届いた列は短く、遅れて気づく列は長く：

| 届き方 | 経過 |
|---|---|
| 緊急で受けた | +6分 |
| 至急で受けた | +15分 |
| 通常で受けた | +30分 |
| 再採血の依頼を受けた | +12分 |
| 通常で流れて、あとで気づいた（`routine` 行以外の `routine` 列、`leak_silent`） | +75分（`hold_mismatch` は `翌 09:10`） |

数字は `data/messages/common.json` の `_doctor_time` に置く。コードに埋めない。

## 6. 生成症例を1本足す

## 7. 実装の形（Code へ）

- `src/review.js`：純関数 `buildReview(judgeResult, caseDef, operation, context) → { headline, reply, doctor }`。
  `reply` は ID の配列（既存の `choices[].reply` と同じ形）、`doctor` は ID。プレースホルダの埋め込みは表示側の一か所（見出しの `{key}` を埋めている関数）に寄せ、`{行動名}` も同じ関数で `{action}` と同じ扱いにする
- `data/messages/common.json`：§4 の40本と §5 の22本、`_doctor_time`。`rookie.json` には足さない（手書きと共通を分ける）。読み込みは既存の messages と同じ辞書に合流させる
- `report.js`：`choices` が無い症例のときだけ `judge()` → `buildReview()`。`choices` を持つ症例は今までどおり
- 医師の `from` `subject` `time` の組み立ては `review.js` の中。5-3 の規則
- `hold_*` 行の列（5-1）の判定も `review.js`。`note` の定義は `data/judge.json` の `comment_rules` から引く（`facts` に `A` か `M` を持つコメント）。コードにコメントIDを並べない
- テスト：
  1. `common.json` に `msg_rv_{P1..P8,O1..O11,best}_{kanae,yusuke}` の40本が全部ある。`emotion` は §3 の対応どおり（P1・P3・P4・P7 は serious/alert、P2・P5・P6・P8 は deadpan/troubled、ok は normal、best は praise）
  2. `msg_dr_*` が22本全部ある
  3. 全部の台詞について、プレースホルダが §2 の5つ以外に無い。`{prev}` を含むのは P7・P8 だけ
  4. 全部の台詞に、辞典のテストで使っている病名の語が無い。患者名（「患者I」「Jさん」のような）と症例番号も無い
  5. judge-rules.md §6 の代表10通り（§2 の各行＋手書きに無い6行）のそれぞれで、best の操作と、代表的なずれ（各型で少なくとも poor 1つ・ok 1つ）を `buildReview` に通し、`headline` `reply` `doctor` が全部埋まり、埋め残しの `{` が無い
  6. `hold_sample`・`hold_mismatch` の5列が、5-1 の条件表どおりに分かれる（通常＋再採血＋note なし → `stopped`、至急＋note＋再採血なし → `note_only`、至急＋再採血＋note なし → `leak_recheck`、通常のみ → `leak_silent`、緊急のみ → `leak_loud`）

  10. 手書き9本のテスト（230件）はそのまま通る（触っていないことの確認）
