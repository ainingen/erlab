# ERLAB 症例 7-b「IDは合っている、中身が違う」仕様（2026-09-09）

roadmap §6-3-c。「調べる」（docs/investigate.md）が入ったので、取り違えを一本手書きして `actions` の使い方を固めてから §6-4（判定ルールの言語化）へ進む。

## 0. investigate.md §11 の骨子からの変更

§11 では「ID照合で不一致（ラベルは同室の別患者）」と書いた。これを **ID照合は一致、中身が別人** に変える。

理由：ラベルの取り違えは受付のバーコード照合で止まる。検査室まで来てしまう取り違えは、ラベルは正しく貼られていて、**中の血が別の患者**のもの（二人続けて採血して、ナースステーションに戻ってから貼った）。この形のほうが実務に近く、教えたいことも深い。

- 症例6で教えたこと：照合してから「患者の変化」と言う
- 7-b で教えること：**照合が一致でも中身は分からない。前回値の中で「変わらないはずの数字」が変わっていたら、別人を疑って病棟に聞く**

この症例で `idcheck` は best の条件に入る（照合はする）。ただし答えはそこにはなく、答えは **MCV** と **電話** にある。

## 1. 症例の骨子

- 整形外科病棟から。78歳男性、右大腿骨骨折の術後3日目。前回値は3日前（術前）
- 届いた値は、同室の45歳女性（鉄欠乏性貧血）のもの。検体状態は空、目視も正常、ID照合も一致
- 前回値と比べると、**Hb は下がっている**（術後の出血に見える。症例6の型に見える）。しかし **MCV が 92 → 76** に落ち、**Cre が 1.32 → 0.55**、PLT・BUN・CRP も向きがばらばら
- 罠：症例6を覚えた人は「術後3日目に Hb 低下 → Δ → 至急」と反射で押す。それは**別人の値を出血として報告する**ことになるので poor
- 型：**MCV は数日で動かない**（赤血球の寿命は約120日。その人の指紋のようなもの）。MCV が短期間で大きく変わったら、患者の変化ではなく検体を疑う
- 電話で病棟に聞くと、同室の患者と続けて採血し、ラベルはステーションに戻ってから貼ったと分かる → 取り違えの可能性 → **値は報告保留、至急で病棟に伝えて再採血**
- 再採血検体は本人の値（術後らしい軽い Hb 低下と CRP 上昇、MCV は前回どおり 92）

## 3. 判定（上から順に評価。先に一致した枝）

`comment` の `mismatch` は「検体取り違えの可能性あり」のコメント。`comment_templates.json` に取り違えのコメントがあればその ID を使う。なければ docs/comment-list.md の作法で一本足す（文案：「検体取り違えの可能性あり。本検体の値は報告保留。再採血を依頼」）。

| 5 | recheck, suspects.MCV=[mismatch] | ok | 疑いは正しい。ただし理由がコメントに残っていません |
| 6 | report=urgent または emergency, suspects.Hb=[delta] | **poor** | 別人の値を、出血として報告しています |

## 8. 実装との差（2026-09-09 実装後に追記）

### `recollect.seed` は拡張不要だった

`buildRecollect()` はすでに `re.seed`（根っこごと差し替え）と `re.overrides`（一本目の根っこに重ねる）の
両方を受けるようになっていた（`src/derive.js`）。書かない症例は今までどおり一本目の seed で動く。
n05b の二本目が変わらないことをテストで押さえた。

### `when.report` は配列を許した（枝は割らなかった）

枝6を二本に割ると、同じ headline・同じ講評・同じ医師返信の枝が二本並ぶ。
`when.report` に配列を書けるようにして「そのどれか」で拾う形にした。文字列で書いた既存の枝はそのまま。
`docs/mechanics.md` 2-b に一行足してある。配列は二つ以上のときだけ使う（一つなら文字列）。

### 取り違えのコメントは既存のものを使った

`comment_templates.json` にすでに `mismatch`「検体取り違えの疑い（前回値と不一致）」がある
（scope=all・常に出る）。文案どおりの新しい候補は足していない。§3 の `comment.must: ["mismatch"]` は
この既存IDを指す。一覧は全症例で同じ、を守るため（docs/comment-list.md）。

### 台詞を二か所だけ直した

| 元（§4） | 直し | 理由 |
|---|---|---|
| 電話の三行目「患者Iさんは朝から変わりなく、創部の出血もありません。」 | 「患者Iさんは朝から変わりなく、いつもどおり過ごしています。」 | 電話は病名・身体所見の示唆を返さない（docs/investigate.md §2）。既存のテストが電話の文面から「出血」を弾いている |
| かなえの「症例6と同じ手を打つ前に」「症例6の手を、別人の値に打ってる」 | 「前の症例と同じ手を打つ前に」「前の症例の手を、別人の値に打ってる」 | 悠介側は §4 の時点で「前回の症例」。かなえだけ症例番号を口に出すのは揃わないので寄せた |

申し送りは二行足してある（前回値の欄を上から下まで見ること／検体状態欄が空であること）。
`from_mentor` の申し送りは指導役の名義で出るので、内容は指導役ごとに分けていない。

### 再採血検体の見出しを一語直した

`renderRecollect()` の前回値欄の説明が「**同じ患者の**最初の検体（…）の値を並べています。」だった。
症例7-bでは一本目が別人の検体なので、この一文だけが嘘になる。全症例で成り立つ
「**この依頼の**最初の検体（…）の値を並べています。」に直した（他の症例では意味は変わらない）。
