## Code に頼むときの型

**マージ**

> `<ブランチ名>` を `main` に入れて push して。
> - `main` で `git pull --ff-only` のあと、早送りできるか確認。できなければ
>   `git rebase main` してから `--ff-only`。衝突が出たら止めて報告
> - push 前に `test/index.html` で全件 PASS を確認
> - push したらローカルのブランチを削除。リモートは触らなくていい
> - `git log --oneline -5` と、`main` と `origin/main` の一致を報告
>
> マージだけ。コードと docs には触らないで。

**実装**

- 仕様は `docs/` にファイルで置いて渡す（`mechanics.md` / `case07.md` / `readable.md` が前例）。
  渡したきりの仕様書は次のセッションから見えないので、**書いたら push**
- 「やらないこと」の節を必ず入れる。守られる
- 実装と仕様の差は、仕様書の末尾に「実装との差」として記録させる
- **作業中のブランチがあるうちは、画像の差し替えでも `main` に直接入れさせない。**
  一度これで分岐して、リベースが要った

**注意**

- **リモートブランチの削除が Code の環境から通らない**（`the remote end hung up
  unexpectedly`）。通常の push は通る。溜まったら手元で
  `git push origin --delete <名前>`。いまリモートに4本残っているはず
- テストはブラウザで `test/index.html` を開く形。Code はそれを実行して報告できる

## 絵の作り方（立ち絵を足すとき）

表情ごとに別々に生成すると**別人になる**。一枚に複数コマを描かせると、一回の生成の中では
同じ人になるので揃う。

- **3コマのシートで出す。**1コマ目は必ず normal にして、残り2つに表情。シート同士を
  並べても normal が共通なので揃う
- 参照は最初の1枚、決まったあとは**採用したシートを丸ごと**添付する
- 表情の指示は具体的に。「見開く」は笑顔や怒りに化ける。**かなえの alert は口を開けて
  「待って」、悠介の alert は口を閉じたまま**（声を荒げない人なので）
- 揃わないコマが出たら、そのコマだけ直さず**シートごと出し直す**
- 切り出し・透過・軽量化はチャット側でやれる（`rembg` の `isnet-anime`。白抜きだと
  白衣ごと透ける）。1枚 110KB 前後、幅 306〜310px
